# 正文渲染与编辑契约

## 1. 博客与云剪贴板

博客与云剪贴板共用 ReactiveMD。阅读入口先按查看者和资源可见性授权，再由 `src/lib/reactive/read-render.ts` 调用编译器。服务端输出静态首屏，浏览器接管组件交互。Markdown 和带组件的正文走同一引擎。单篇编译失败返回不可用状态，保留作者源码供修复。

数据库保存正文源码与所需元数据。增强语法以 `syntax_version` 表示，对外的 `format` 字段由它派生。迁移 46 退役了独立的 `format` 列；旧客户端提交的该字段只作白名单校验。编译结果只进有界进程缓存；与查看者有关的引用数据在当前请求中准备。写服务在保存或发布时编译源码；失败返回 `content_unrenderable`。历史字段 `renderer_override` 用于既有接口兼容，渲染选择由读取入口负责。

成员视图按业务读口的权限展开引用。对外视图保留受限引用的原文，图床与音频仍由各自资源路由判权。预览与导出沿用同一可见性边界，预览中的交互控件不能产生投票等业务写入。作者语法见 `docs/guide/内容引用语法指南.md`。

引用里没有「按格式分流」这一档：能读到的剪贴板**一律内联正文**（子文档独立编译，作用域与父正文隔离，不套卡片或外壳），读不到给不可点的占位。评论 / 讨论是另一条管线，规则见该指南。

## 2. 评论、讨论与故事

评论由客户端 `rich-text.ts` 通过 marked、DOMPurify 和受控的 DOM 引用渲染。按资源类型核对可见性；引用限制及评论代码块里的历史例外见 `docs/guide/内容引用语法指南.md`。

讨论同样保存原始正文。浏览器使用聊天专用 ReactiveMD 配置，允许 Markdown 和公式，作者组件、原生图片、表达式及扩展 HTML 降级为源码。每页由一个 Worker 编译视口附近的消息，Manager/Worker 按查看者跨页面复用，最后租约释放 10 分钟后回收，切账号/登出立即清空；失败时保留源码。引用在编译后的 AST 中转换为 `chat-ref`，8 位剪贴板最多内联一条（Markdown 与 ReactiveMD 都内联），宿主按当前查看者校验每个槽位和资源。站内链接、HTTP(S) 和 mailto 有各自的处理规则，图片限于受控本站路径。实现入口见 `docs/agent-domain-rules.md` §2.13。

机器人生成任务暂存在主站内存。临时预览沿用频道可见性，既不推进消息游标，也不影响未读、提及与侧栏。正式发布通过既有发送服务，仍执行权限、限额与通知逻辑。协议见 `docs/bot/chat-bot.md` §7.8。

故事来自维护者提供的 `instance/stories/`，由 `src/lib/story-service.ts` 在服务端处理。文件格式与脚本入口见 `docs/guide/story-module.md`。

## 3. 编辑、导出与运维

编辑器插入面板由各资源模块生成引用串；工具条与拖放共用图片 Markdown 生成函数。HTML 导出和打印读取点击瞬间的编辑器源码，重新编译。站内资源地址按原页面解析，同页锚点指向导出件，访问媒体仍需原有权限。用户操作见 `docs/guide/编辑器使用指南.md`，实现入口为 `src/lib/md-editor/`。

手写 SQL 迁移、旧语法升级和公开搜索索引重建各有独立入口。编译缓存可在进程重启后重建，公开索引的回填步骤见 `docs/deploy.md`。
