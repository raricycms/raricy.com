# 编辑器换代方案（Vditor → CodeMirror 6）

> **状态：M0 / M1 / M2 已实施（2026-10），M3 / M4 未实施。**
> 本文规定的目标、实现边界、分期和验收条件继续有效；各期的实际交付、与本文的偏差
> 与已知限制集中在 §7 末尾的「实施记录」——**那才是现状，别只看这张表**。
> 已落地的形状：CodeMirror 6 保存与编辑 Markdown 原文，完整预览与正文共用同一台
> 渲染器（`MarkdownRenderer`），首版是源码编辑加可切换的完整预览；
> 就地装饰（在源码里直接看到图片 / 公式）属于 M3，**未做**。

## 1. 目标与需求边界

### 1.1 已知问题与尚未确认的偏好

现有反馈涉及三件事：

1. 编辑工作流不顺手，粘贴代码时还会自动补代码围栏。
2. 博客与剪贴板编辑页缺少站内资源选择入口，内容引用需要手打，不能预览。
3. Vditor 的展示结果与发布后的正文存在格式差异。

反馈中「不适应 Typora 的工作流」与「希望像 Typora 一样就地渲染」不是同一个需求。
现有两处表单已经使用 Vditor 的 `ir` 模式，不能仅凭这一点推断用户想要更彻底地隐藏源码。
**编辑布局和源码隐藏偏好仍需通过原型确认。**

本方案先采用一个可以继续调整的默认值：Markdown 原文始终可编辑，用户能切换完整预览；
宽屏可以并排显示，窄屏切换编辑与预览。这个默认值不是已确认的用户偏好，也不把就地
渲染列为替换内核的先决条件。

### 1.2 本次换代必须交付的行为

- 纯文本粘贴以 `text/plain` 为准，不根据剪贴板中的 HTML 自动补围栏或改写 Markdown。
- 博客发布 / 编辑、剪贴板新建 / 编辑共用一个编辑组件，继续保存 Markdown 原文。
- 保留两处新建页的本地草稿，以及剪贴板已有的手动保存和自动保存。
- 保留图片上传、拖拽和粘贴入口，完整预览能显示图片、公式及既有内容引用。
- 提供收藏夹、图床、音频、投票、剪贴板五类资源选择入口。
- 完整预览与正文使用同一条渲染管线；亮 / 暗主题跟随站点。

文本粘贴与图片粘贴分别处理。剪贴板同时含文本、HTML 和图片时，以用户明确粘贴的
纯文本为优先；仅含可接受图片时走图片上传。混合内容的处理需有固定规则和测试，
不能为了找图片先阻断正常文本粘贴。

### 1.3 本次换代范围之外

- 从零实现文本引擎、富文本文档模型或 HTML → Markdown 自动转换。
- 默认隐藏源码、整篇就地渲染、可视化表格编辑。
- 扩展博客 / 剪贴板的引用种类：表情和用户名片暂不接入这两处。
- 在预览里投票或执行其他业务写操作。
- 模拟匿名读者、其他账号或所有可见性档位的预览。

表格仍可写 Markdown 源码并在完整预览中查看。导出、大纲、全屏等能力的处理见 §7；
它们是否进入首版，需要在替换前明确记录，不能靠删除旧工具条隐式决定。

### 2.2 选择 CodeMirror 6 的理由

选型判据是：**Markdown 原文是权威文档，完整预览只有一条权威渲染管线。**
编辑器是否附带可选渲染功能，不是单独的否决理由；关键在于本站有没有绕过它、复用
正文管线，以及是否会为了编辑而往返转换原文。

| 路线 | 本项目的取舍 |
|------|--------------|
| Vditor 加资源面板与独立站点预览 | 可以改善插入与预览；仍需维护原来的 IR 输入行为和集成适配，可作为短期方案 |
| **CM6 + 本站集成层 + 正文预览** | 直接编辑文本，选区 / 撤销 / 语言支持有现成内核；装饰可逐步增加，选定为长期路线 |
| ProseMirror / Milkdown / Lexical 富文本路线 | 需要定义文档模型、导入导出和原文保真规则；目前没有足够的富文本需求支持这笔投入 |
| 从零实现 contenteditable 编辑器 | 输入法、选区、撤销和跨浏览器行为均需自行承担，不采用 |

CM6 自身也使用 `contenteditable`。它的优势是成熟的文本状态模型、事务和输入处理，
不是避开了这一浏览器机制。粘贴改写与输入法组合输入也应分别验证，不能视为同一个问题。

CM6 的 Markdown 语言包提供 CommonMark 与扩展 Markdown 语言。实施时显式选择
`markdownLanguage` 并配置 `markdown({ base: markdownLanguage })`，验证表格、任务列表
和删除线；编辑侧语法树用于辅助编辑，不取代 marked 的终稿语义。

不在本文维护「最新版」和各包独立打包大小的表。实施时记录选用版本与锁文件，比较
实际编辑页的 JS / CSS / 字体请求、压缩传输量和解析开销。npm 包解压大小不能与 gzip
传输大小直接比较，也不能把依赖包各自的打包结果相加当成页面载荷。

技术依据：

- [CM6 系统指南](https://codemirror.net/docs/guide/)
- [装饰示例](https://codemirror.net/examples/decoration/)与[API 参考](https://codemirror.net/docs/ref/)
- [Markdown 语言定义](https://github.com/codemirror/lang-markdown/blob/main/src/markdown.ts)与[配置入口](https://github.com/codemirror/lang-markdown/blob/main/src/index.ts)

这些链接用于说明 API；锁定依赖时以所选版本的源码和类型定义再核对一次。GitHub 镜像
是否归档，不单独作为项目停止维护的证据。

## 3. 架构与一致性承诺

### 3.1 分层

```text
BlogForm / UploadForm
    └── MarkdownEditor
        ├── EditorShell：工具条、布局、面板、状态
        ├── CM6：Markdown 原文、选区、事务、撤销
        ├── 资源插入与上传：只通过事务修改原文
        ├── 草稿适配：由调用方提供新建 / 编辑上下文
        └── 完整预览：复用 MarkdownRenderer 与共享正文管线

MarkdownRenderer / 后续可选 widget
    └── 共享渲染与引用模块
        ├── 整篇引用预处理 + 资源读取
        ├── 公式保护 → marked / hljs → 还原 → DOMPurify
        └── DOM 后处理：MathJax、外链、图片、投票展示
```

CM6 实例持有文档状态。React 接收修改通知、驱动面板和预览，不在每次输入后重建编辑器，
也不把整篇字符串重新灌进 CM6 来模拟受控输入。重置文档必须是明确操作。

### 3.2 完整预览承诺什么

**相同 Markdown 原文、引用读取模式和引用数据快照，应产生相同正文结构与样式。**
完整预览复用正文的语法、净化白名单、代码高亮、公式配置和引用预算，不单独实现一套
「看起来接近」的转换器。预览里的资源取数复用共享 resolver，不另外请求一遍。

首版预览是当前作者的读取视角。本人能读到私有素材，不代表其他成员或匿名读者也能
读到；资源面板应标明私有状态，相关边界沿用既有读口。对外模式仍由服务端决定，
保留 `contentRefs` 和 `externalClips` 的现有语义，不为了编辑器放宽 API 权限。

引用内容可能在编辑期间或发布后变化。一致性以同一份引用快照为比较条件，不承诺
发布后的最新资源永远与先前预览相同。提供「刷新预览」以重新读取引用。

预览使用共享的投票展示结构，但不绑定投票提交处理器。正文保留现有交互；只读预览
差异由显式的交互参数控制，不通过复制投票组件实现。外链和素材链接不能覆盖当前编辑页。

### 3.3 为什么 widget 不等于完整预览

剪贴板引用先把正文拼进整篇 Markdown，再统一解析。引用内的列表、链接定义、代码
围栏等可能影响引用之外的内容。例如引用里未闭合的代码围栏，会改变后续正文的解析。
逐个 token 独立渲染，再拼成 widget，无法保证得到同样的结果。

隐藏标题标记、强调符号或链接 URL，也需要自己的语法判断和样式。Lezer 与 marked 的
语法树并不因此成为同一份。后续装饰只能承诺支持范围内的辅助显示，完整预览始终是
核对终稿的入口。若将来要求就地显示与整篇终稿严格等价，需另行设计源文到展开文档的
位置映射，不能把它当作普通 token widget 的小补丁。

### 3.4 前置重构的边界

建议拆出以下职责，名称在实施时可调整：

| 模块 | 职责 |
|------|------|
| `content-ref-processor` | 保留整篇引用扫描、替换顺序、代码屏蔽、预算与降级语义 |
| `content-ref-resolver` | 读取剪贴板 / 投票 / 收藏夹，保留完整解析结果，去重与管理缓存 |
| `blog-renderer` | 整篇公式保护、marked / hljs、公式还原、DOMPurify，返回 HTML 与后处理所需数据 |
| `blog-content-dom` | 有生命周期和清理入口的 DOM 后处理；正文交互与只读预览分开配置 |
| hljs 主题 hook | 共用亮 / 暗主题样式，处理多个实例并存时的生命周期 |

已有 `src/lib/blog-markdown.ts` 的净化白名单与投票安全构造继续作为权威。
`src/lib/markdown-math.ts`、`src/lib/audio-refs.ts` 和 `src/lib/favorite-refs.ts`
沿用现有职责。拆模块不得引入 Prisma 或其他服务端依赖到客户端包。

M0 先保持正文行为不变。可提供按 token 读取资源的接口，但它不负责决定整篇替换位置
或预算，也不代替整篇渲染入口。现有语法的兼容范围，包括数字 ID 引用中的空白容忍，
不能在抽模块时顺便收紧；具名 token 继续遵守白名单和不含空白的规则。

## 4. 资源面板、插入和上传

### 4.1 五类入口与复用范围

| 资源 | 现有列表读口 | 首版插入结果 |
|------|--------------|--------------|
| 图床 | `GET /api/images`，自己的未删除图片 | 标准图片 Markdown，沿用当前上传插入形状 |
| 音频 | `GET /api/audio`，自己的未删除音频 | `[@音频/<10位ID>]` |
| 剪贴板 | `GET /api/clipboard`，自己的未删除剪贴板 | `[@<8位ID>]` |
| 投票 | `GET /api/votes`，自己创建的未删除投票 | `[@<9位ID>]` |
| 收藏夹 | `GET /api/favorites`，自己的收藏夹 | 仅有 `public_id` 的公开收藏夹可插入 `[@<6位数字ID>]` |

图床可复用 `src/app/components/ImagePickerModal.tsx` 的列表、搜索和渐进展示，适配
回调即可；其余四类新增面板。不要同时把图床计入「已有组件」和「必须新写的组件」。

这些读口目前没有通用服务端分页和搜索。首版在已取得的列表上过滤并渐进展示；如果
实际数据量要求服务端分页，再单独扩展接口，不能把客户端截断写成已经有分页协议。
面板沿用现有账号权限，不创建跨账号的资源广场；手动输入引用仍由实际读口判权。

表情与用户名片选择器目前用于评论 / 讨论。它们产出的 token 不被博客 / 剪贴板终稿
支持，因此首版不直接复用。若未来扩展，须同时更新终稿、匿名视图规则、预算、指南
与测试，不能只在编辑器里做一个会显示的 widget。

图片上传和图床选择默认统一插入 `![描述](/api/images/<id>/raw)`，保持现有上传行为。
用户已有的 `[@<10位ID>]` 继续支持，不自动改写存量内容。两种形状的引用预算并不相同，
不得为了统一按钮而改动正文的既有数量限制。标准 Markdown 也不保证私有图片对站外可读。

### 4.2 插入必须走 CM6 事务

`src/app/components/textarea-insert.ts` 可参考选区捕获与焦点恢复的交互语义，不能直接
复用 textarea 的赋值、`setSelectionRange` 和量高实现。

- 打开面板前捕获选区；期间发生文档修改时，通过事务的 change mapping 更新插入区间。
- 工具条命令、token 插入、图片完成插入统一 dispatch，进入撤销历史。
- 明确多选区策略：格式命令可逐区间应用，资源选择首版只作用于主选区。
- 面板取消不改原文；确认后恢复编辑焦点和选区。键盘操作与移动端焦点行为需验证。
- 不对 CM6 管理的编辑 DOM 直接赋值或改结构。

### 4.3 上传生命周期

复用 `src/lib/image-client.ts` 的单文件校验、XHR 上传与弱网重试。它不负责选图、
拖拽事件、多文件调度或 CM6 插入；总体积常量也不是自动执行的多文件闸门。

集成层负责多文件校验和有限并发、进度 / 失败提示、插入位置及撤销。先保留每次上传
操作的锚点，并随事务映射；操作之间独立管理。多选按用户选择顺序插入，不能由网络
完成顺序决定排版。上传占位状态不写进持久化 Markdown。

用户删除上传锚点、撤销操作或离开编辑页后，迟到的结果不得重新插回原文。已成功
上传的资源仍留在图床；不能通过物理删除素材来补偿一次取消的编辑操作。

## 5. 缓存、异步与草稿

### 5.1 引用解析与缓存

缓存默认限于当前编辑会话，跨预览重渲染复用，编辑器销毁时释放。缓存键至少包括
资源类型、ID、读取模式；如果以后跨编辑实例共享，还必须隔离账号 / 会话上下文。
匿名 `externalClips` 使用调用方提供的快照，不复用成员模式的数据。

- 同一资源的并发读取复用 in-flight Promise；正文和投票后处理共用返回数据。
- 缓存只保留当前文档所需资源，并设容量上限。失败不能永久驻留：手动刷新可重试，
  自动重试有次数上限，不在每次按键时重试。
- 预览更新防抖并使用文档版本 / generation；旧响应可充实合法缓存，但不得覆盖较新的预览。
- 卸载时取消或忽略未完成请求，不向已经销毁的编辑器 dispatch。
- 「刷新预览」使当前引用缓存失效并重新请求；401 / 403 按现有降级口径处理，不能
  用上一份成功缓存掩盖本次拒绝。
- 替换名额按整篇文档及既有处理顺序计算，不按视口、唯一 ID 数量或各 widget 单独计算。

保留 `MAX_BLOG_REF_ITEMS`、收藏夹与音频的独立上限以及各自降级行为。代码屏蔽与
嵌入内容的扫描顺序沿用正文规则；缓存命中不会给超预算引用额外展示名额。

### 5.2 两处本地草稿

新建页保留原有正文缓存键和纯文本内容：

| 场景 | 键 | 初始行为 |
|------|----|----------|
| 博客新建 | `blog-upload-editor` | 恢复旧草稿；成功发布后清除 |
| 剪贴板新建 | `clipboard-upload-editor` | 恢复旧草稿；成功创建后清除 |
| 两处编辑态 | 不使用上述新建键 | 从服务端原文初始化，不覆盖或读取新建草稿 |

不把两处草稿合成一个键，不为了改格式丢弃旧缓存。首版仍保存正文，不暗中扩成标题、
可见性等整张表单缓存。读取失败或 localStorage 不可用时允许继续编辑，并显示无法
保留本地草稿的提示；保存失败不得清草稿。

监听最新文档状态进行防抖写入，页面离开时尽力落下最后一份。发布成功后先停止待执行
的草稿写入，再清键，防止延迟回调把刚清掉的草稿写回来。新建时若同时存在服务端
初值和本地草稿，提示恢复选择，不静默覆盖任一份。

未来若要按账号隔离草稿，需要另写旧键迁移规则；本次不把历史键替换成不可读取的新键。

### 5.3 保存与失败回退

剪贴板的 Ctrl / Cmd+S、每分钟自动保存及其偏好
`localStorage.clipboard_autosave_enabled` 仍由表单负责。编辑器提供同步的最新原文
读取口，不从防抖后的预览状态取提交内容。避免同一次保存被 CM6 快捷键和页面监听重复触发。

组件初始化失败时保留基础 textarea 回退；编辑中若辅助预览或装饰失败，关闭该辅助
能力并继续编辑，不清空原文。两处表单的禁言判定、提交接口、长度校验和可见性规则
不在本次换代中改变。

## 6. 就地装饰的后续设计

### 6.1 启用条件与支持边界

就地装饰默认关闭。先用原型确认隐藏标记是否改善实际工作流，再按明确清单启用。
源码模式与完整预览必须一直可达；装饰出错时能退回源码显示。

第一批可考虑标题 / 强调 / 删除线标记、图片和音频辅助预览。剪贴板展开、跨行公式、
表格和复杂引用块分别验证，不能承诺它们只是同一个 widget 的不同皮肤。

选区与组合输入相交的语法区间保留源码；不简单套用「光标行」处理跨行语法。要定义
点击、方向键、拖选、复制和删除的行为，以及 widget 如何回到可编辑的 token。

### 6.2 CM6 装饰的提供方式

**同步计算装饰不意味着装饰只能来自 ViewPlugin。**

- 行内标记、搜索提示等不改变块布局的装饰，可由 `ViewPlugin` 根据视口计算。
- 块级 widget 和覆盖换行的替换装饰，放在 `StateField<DecorationSet>` 中，直接向
  `EditorView.decorations` 提供；不能通过依赖视口的间接装饰提供。
- 异步 resolver 将结果通过 `StateEffect` 写入状态，再同步生成装饰。
- 装饰区间随事务映射；需要整体移动 / 删除的范围使用 `atomicRanges`，同时定义
  点击显示源码的方式，不能让 token 成为无法进入的对象。
- 图片加载、音频元数据和公式排版改变高度时，请求重新测量；widget 复用与销毁要
  保留播放状态并清理事件，不能每敲一个字就重建媒体 DOM。

### 6.3 输入法与性能

组合输入期间保持活动区间的源码和 DOM 稳定，延后会替换该区间的装饰更新。文档仍
正常更新，已有区间仍须随事务映射；不能把「暂停装饰」实现成丢弃输入或停止位置映射。
组合结束后处理积压结果并重算，具体时序以 CM6 所选版本与真实输入法验证为准。

视口外的轻量装饰按需计算，整篇引用预算仍独立计算。正文最大 250000 字符，引用还
可能展开成长内容；不能每次按键同步执行整篇 hljs 自动识别、MathJax 和 DOM 重建。
完整预览防抖且可关闭，性能不足时保留手动刷新，不默认把问题转移到更多请求或无限缓存。

## 7. 分期、发布与回滚

每期有独立提交和验收范围。回滚是退回前一期代码与资源配置，文档格式和数据库不随
编辑器切换；本方案不需要 schema 迁移。不要通过在首版产品里长期维护两个编辑器来
代替回滚方案。

| 期 | 交付 | 完成条件 | 状态 |

| **M0** | 抽共享引用 / 整篇渲染 / DOM 后处理 / 主题模块 | 两处正文行为不变，成员与对外模式回归通过 | ✅ 已实施 |

#### 7.1.1 加固轮（2026-10，交付后复审）

第一版交付后过了一轮外部复审，逐条修完后**新增的限制**记在这里（实现与理由在各自
文件头，不在这里复述）：

- **上传图片的 alt 文本里，方括号写成 HTML 实体**（`![图&#91;1&#93;.png](…)`），
  反斜杠和换行按标准 Markdown 处理。**不能改成 `\[…\]`**：那正是 LaTeX 块级公式的
  定界符，公式保护先于 Markdown 解析出手，会把这一段吃掉（顺带把公式计数 +1），
  表现是 alt 里凭空多出反斜杠。见 `src/lib/md-editor/upload.ts` 的 `escapeAltText`。
- **导出件只保证「正文 + 已经展开的内容」自足**：正文里的站内相对地址补成了站点
  绝对地址、导出件内部的 `#锚点` 留在文件自己身上（**故意不写 `<base>`**）、代码块的
  复制按钮摘掉。但**样式表与媒体仍要联网**，而且按站内读口判权 —— 私有图 / 私有音频
  在别处打开读不到，MathJax 的字体也一样（它是 `url(/static/mathjax/…)`，只补了地址）。
  没有做「把媒体打进压缩包或内联成 `data:`」的打包器，别把它当成待补的缺口：
  那会绕开权限判定。
- **打印等的是「资源画得出来」**，不是「写完 iframe」：等 `document.fonts.ready` 与
  未完成的 `<img>` / `<link>`，**上限 3 秒**（`PRINT_READY_MAX_MS`）。到上限照打，
  绝不吊死；走的是隐藏 iframe，没有 `window.open` 弹窗那条路。
- **引用展开是单趟的、不递归**：正文里引用出来的剪贴板正文，其中再出现的 `[@…]`
  不再展开。这是 M0 就跟下来的口径（草稿内容里的 token 不该在别人的文章里二次取数），
  不是这一轮的缺失。
- **保存保护只覆盖「提交了这一趟、回来之后又改过」**：新建页照发但**提醒**（并把还有
  哪些字段变了写进提示），编辑页**不跳转**，让人自己再存一次。判据是提交时那一趟的
  字段快照（标题 / 摘要 / 可见范围 / 正文都在内），不是只比正文。**编辑态的本地草稿
  仍然没有**（沿用旧行为，见上一条）。
- **导出 / 打印取的是**当下**的正文**：走的是同一套渲染管线（`ContentRefProcessor` →
  `renderBlogMarkdown` → `enhanceBlogContent`）在离屏容器里现渲一份，**不读**预览那棵
  防抖 DOM。文件名与 `<title>` 都取此刻的标题；渲染失败给一条错误提示，不产出半成品。
- **性能取数仍然没有**（§9.3 那条预算项依旧空着）：这一轮只钉住了「同一份正文的重复
  渲染不再重发投票请求」这一条可回归的行为（`tests/unit/md-editor-preview-votes.test.ts`），
  长文延迟与预览耗时仍无实测。
- ⚠️ **引用预算不能挪到取数之前**（复审提过一版「省掉不会展开的那些请求」）：名额是
  「**取到了才占一格**」的 —— 取不到的（超预算 / 被拒 / 404）保持字面量、**不吃**后面
  那些取得到的名额（`content-ref-processor.ts` 里那句 `continue` 就是这件事）。所以
  哪些引用会被丢掉，**只有取完才知道**；按扫描顺序提前截断会在「前面几条恰好取不到」
  时少展开后面本来出得来的引用，屏幕上看着只是「引用没展开」，不报错。

## 9. 验收与守卫

### 9.1 共享语义

- 编辑器不得引入独立 Markdown → HTML 转换路径；静态依赖检查只能辅助，不能代替
  真实渲染结果对比。共享模块本身允许使用 marked。
- 固定引用数据、读取模式和原文后，比较完整预览与正文的结构和样式；交互模式差异
  单独断言。覆盖引用影响上下文、重复 ID、预算边界、错误降级与代码屏蔽。
- 每类面板输出通过对应语法校验，再走真实整篇渲染；具名 token 的字符集和无空白
  约束同源。保持既有表情 / 名片在博客里不展开的规则。
- 成员模式和匿名对外模式的数据不串用；私有素材、公开剪贴板、收藏夹和投票维持
  现有读口边界。预览切换、关闭与刷新不产生业务写请求。

M0 先建立现有行为基线。若暴露既有代码屏蔽或引用顺序的缺陷，单独记录并修复，不能
在「无行为变化的抽取」里悄悄改语法或预算。

### 9.2 编辑与保存

- 无围栏代码的纯文本粘贴不自动补围栏；已有围栏、反引号、缩进和中文保持原文。
- 同一内容分别以仅 `text/plain`、同时带 `text/html` 的剪贴板输入验证，特别覆盖从
  代码编辑器复制的内容；图片粘贴和混合内容按 §1.2 的固定规则处理。
- 工具条、面板、上传插入的位置正确，撤销 / 重做不破坏原文；上传期间继续编辑、
  删除锚点、多选乱序完成、离页后完成均有回归。
- 两处旧草稿都能恢复；编辑态不读新建草稿；失败不清草稿；成功后延迟写入不复活草稿。
- 剪贴板手动 / 自动保存读到最新正文，提交前不等待预览；禁言与长度上限不变。
- 主题切换、编辑页离开后的文章高亮、初始化回退、窄屏布局和键盘操作通过。

### 9.3 异步、真实设备与性能

- 重复引用只发一次并发读取；输入与光标移动不重复取相同数据；刷新能重取。
- 慢请求、乱序响应、网络失败、权限拒绝和组件卸载不覆盖新状态或恢复被取消的插入。
- M1 用真实中文输入法验证基本编辑；M3 再验证装饰区间的 composition。合成
  composition 事件只作辅助，不能代替桌面中文 IME 与移动端 Safari / 微信等实际环境。
- 记录短文、接近 250000 字符的长文及引用展开后长文的输入延迟、预览耗时和请求数。
  发布前依据旧实现基线定下预算；若完整预览持续阻塞输入，先调整更新策略再发布。
- 新测试断言行为，避免绑定 `.vditor--dark` 等已移除类名，或换成等价脆弱的 CM6 DOM 细节。

按改动运行相关单测和 e2e。改了 `src/` 必须先 build；`npm run e2e` 使用现有产物，

> **这一节按「当时提的问题」原样保留**，逐条现状见 §7.1：1 首版布局已定（源码编辑 +
> 可切换的完整预览）；2 导出按 M1 要求交付，**全屏未做**、**大纲未做**、字数统计已有；
> 3 基线**没有记录**；4 表情 / 名片与可视化表格都**没有**混进本次替换，匿名读者视角
> 预览未做 —— 第 4 条里列的几种能力今天仍然一条都没加。

1. 用一个包含代码粘贴、图片、公式和引用的原型确认首版布局。源码编辑与完整预览
   是当前建议，是否增加隐藏标记在 M3 前由实际使用反馈决定。
2. 明确导出是否为 M1 发布要求，以及大纲 / 全屏 / 字数统计的范围，形成旧能力对照表。
3. 记录版本、资源体积和输入性能基线，设定 M1 发布验收预算。
4. 如果需要匿名读者视角预览、表情 / 名片或可视化表格，另行补充权限、语义与验收，
   不默认混进本次替换。

两处编辑器迁移和五类资源集成都可用，而不是 CM6 实例能输入文字。
