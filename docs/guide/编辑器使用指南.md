# 编辑器使用指南

博客发文（`/blog/upload`）与云剪贴板（`/clipboard/upload`）用的是**同一个** Markdown
编辑器，快捷键与绝大多数按钮两边一致 —— 唯一的差别是**公式**：只有云剪贴板有
（博客正文不带公式按钮，云剪贴板的工具条上才有它）。

## 手机上的工具条

窄屏（≤767px）工具条默认只留三件最常做的事 —— **表情**、**上传图片**、**插入引用** ——
其余全部收在**「更多工具」**里：标题、粗体 / 斜体 / 删除线、链接、无序 / 有序 / 任务列表、
缩进、引用、代码块、行内代码、表格、撤销 / 重做、导出（云剪贴板另多一颗**公式**）。

点一下「更多工具」展开，再点一下收起。**展开时那颗开关自己不会挪位置**，所以连点两下
不必重新瞄准；展开出来的按钮接在同一行里往后排，一行排不下就换行，不会被裁掉。

宽屏（≥768px）没有这颗开关 —— 工具条本来就是完整的一排，手机首行那三件与「更多工具」
里的那些**原样都在**。

## Enter 与 Shift+Enter

- **Enter** 保留 Markdown 的书写习惯：在 `- 列表项` / `> 引用` 那一行末尾回车会**接着
  续写下一项的标记**；光标正夹在一对**空**括号中间（`[文字](|)` 那个位置）时会**多补
  一个空行**。
- **Shift+Enter 只换一行**：它什么都不多做，就在光标处插**一个**换行。地址、歌词、
  「想换行但不想分段」的地方用它。

两个键写进正文的**源码**因此不一样（Enter 可能带上列表标记、或者多出那个空行；
Shift+Enter 永远只是一个 `\n`）。渲染两边是**同一条管线**，所以最后看到什么，只取决于
正文里到底写了哪些换行：本站的渲染开关是 GFM + `breaks`，**普通段落里单个换行就显示成
换行**（不必写 `<br>`，也不必在行尾补两个空格），**连着来两个才是新的一段**。这一条说的
是普通段落 —— 代码块里怎么显示由代码块自己决定，与按哪个键无关。

## 放进正文的资源

音频、剪贴板、投票、收藏夹这四类内容走**「插入引用」**（挑一条已有的），落进正文的是
一枚 `[@…]` 引用。

**图片不一样**：不管是从「插入引用」里挑一张已有的、还是点「上传图片」新传一张，
落进正文的都是**标准 Markdown 图片** `![文件名](/api/images/ID/raw)` —— 它是 Markdown
自己的语法，不是 `[@…]`。

那四种 `[@…]` 引用各自的语法见 `docs/guide/内容引用语法指南.md`。引用在**预览、导出、发布后**
用的是**同一台渲染器**，所以它那几道上限（最多替换 50 处、需要取数的引用最多 50 个、展开后正文
合计封顶 50 万字符）在哪儿都一样 —— 超出的引用在预览里也**原样显示**为那串 `[@…]`，不是预览坏了。

## 工具条上还有的

- **标题**：下拉里选级别，选「正文」会脱掉 `#`。
- **表格**：插一套三行的骨架（表头 / 分隔 / 一行内容），接着自己往下加行。
- **导出**：导出 HTML，或走打印另存为 PDF。
- **预览**：**预览区域不直接编辑正文**（那一块只是看的地方），正文照旧靠上面的工具条
  改、预览跟着刷新。窄屏不提供「并排」这一档，宽屏才有。
