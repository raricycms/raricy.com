# 内容引用语法 `[@ ]` 使用指南

在正文里写 `[@<内容ID>]`，渲染时就会自动嵌入剪贴板文字、投票组件、图床图片或收藏夹卡片。
系统根据 ID 长度自动识别内容类型。

音频那一条是**例外**：它不按长度，而是写成 `[@音频/<ID>]` 这样一个带名字的形式
（ID 长度早被占满了，见「二、一览表」）。

能用的地方有四处：**博客文章正文**、**云剪贴板正文**、**评论区**、**讨论区**。四处支持的
引用类型**不完全一样** —— 先照「一、三步上手」把最常用的走一遍，再用「二、一览表」查语法、
「三、四处地方，支持的不一样」看差异。

---

## 前置条件

- 需要已登录且通过邀请码认证（Core 用户及以上角色）
- 四种内容各有各的加载条件：剪贴板与图片需为公开状态，或你本人是作者；投票没有公开 / 私密之分，Core 及以上都能看到任意未删除的投票；收藏夹**只能引用公开的**（私密收藏夹没有对外 ID，见「三、四处地方，支持的不一样」）
- 单篇博客的显示上限是**三档各自独立的**：主循环最多替换 **50 处**（剪贴板 / 投票 / 图床图片共用这一个额度），**收藏夹最多 3 张卡片**，**音频最多 3 个播放器** —— 收藏夹与音频不占主循环那 50 处
- 取数另有一道闸：**需要取数的引用（剪贴板 / 投票 / 收藏夹）一轮最多取 50 个**，图床图片与音频只拼地址、不占这个名额，同一个 id 引多次也只算一个。**没排进这前 50 个候选的引用，连请求都不发**、原样保留；已经排进候选、只是展开时排不上号的那些则可能已经取过数了
- 长度限制落在**单条**上：一条剪贴板正文最多 5 万字；整篇没有额外的总字数闸，能不能全部显示由上面两条额度决定
- **剪贴板引用不会再展开**：一段剪贴板正文里若又写了 `[@8位]`、投票或收藏夹，那一层原样显示。图床与音频只拼地址、不取数，从剪贴板带进来的仍会正常显示

## 一、三步上手

三个最常用的动作，照抄即可。每一步背后的完整规则都在后面的分类型章节里。

### 1. 在博客里插一张图床图片

1. 打开 `/image/`，在图片卡片上复制它的 10 位 ID；
2. 在正文里就地写下这一行：

   ```
   [@AbCdEf1234]
   ```

3. 发布后打开文章详情页 —— 那一行会变成图片，点一下原地放大（不新开窗口）。

图片必须是**公开的**（或你自己就是上传者），否则别人看到的是一张裂图。
完整规则见「六、图床图片嵌入」。

### 2. 在博客里嵌入一段剪贴板

1. 打开 `/clipboard/`，复制那段的 8 位 ID（列表里、或详情页 URL `/clipboard/<ID>` 里都有）；
2. 正文里写 `[@a1b2c3d4]`；
3. 发布后，那段剪贴板的**正文**会直接排进你的文章里：Markdown 与 ReactiveMD 一样，
   标题、列表、代码块、组件都照原样显示，不套卡片、不留回链。权限与上限见
   「三、四处地方，支持的不一样」。

### 3. 在评论 / 讨论里发一张图

最省事的路是**不用记 ID**：点输入区的「从图床选择」，弹出你自己的图片列表，挑一张即可。
手打 `[@AbCdEf1234]` 一样有效。

⚠️ 评论与讨论里能展开的东西比博客**少**（投票、收藏夹都不展开，剪贴板只展开第一条），
差别逐条列在「三、四处地方，支持的不一样」。

## 二、一览表

> 标题刻意不写「几种」：这张表加过行（表情、名片），而标题不会跟着动 ——
> 曾经就写着「三种」却列了五种。

| 语法 | ID 长度 | 内容类型 | 渲染效果 |
|------|---------|----------|----------|
| `[@123456]` | 6 位 | 收藏夹 | 渲染成一张卡片（标题 + 条目数 + 前 10 篇链接），**仅博客 / 剪贴板** |
| `[@a1b2c3d4]` | 8 位 | 云剪贴板 | 内联正文（博客 / 云剪贴板正文与讨论消息，Markdown 与 ReactiveMD 一样）；评论只内联 Markdown 剪贴板 |
| `[@vOtE12345]` | 9 位 | 投票 | 渲染为可交互的投票小部件（**仅博客 / 剪贴板**） |
| `[@AbCdEf1234]` | 10 位 | 图床图片 | 渲染成图片 `/api/images/ID/raw`，可点开放大 |
| `[@音频/AbCdEf1234]` | —— | 音频 | 渲染成播放器 `/api/audio/ID/raw`（**四条管线都支持**，最多 3 个，见[音频床使用指南](音频床使用指南.md)） |
| `[@合集/表情]` | —— | 表情包 | 行内表情图（**仅评论 / 讨论**，见[表情包使用指南](表情包使用指南.md)） |
| `[@用户/张三]` | —— | 用户名片 | 行内名片（头像 + 头像框 + 用户名，点进主页）（**仅评论 / 讨论**，见第七节） |

ID 长度不在 6 或 8-10 之间的 `[@...]` 不会被处理，以原文形式保留。其中 **6 位必须全是数字** ——
`[@abcdef]` 这种 6 位字母不会被当成收藏夹，一样原样保留。8-10 位：博客 / 云剪贴板正文走
ReactiveMD 管线，沿用旧博客的宽松口径（`\w`，**下划线也认**）；评论走 DOM 管线、讨论走
聊天专用 ReactiveMD AST 适配，后两者都只认**字母和数字**。系统生成的 ID 本来就是字母数字，
正常引用不受这个差异影响，只是别手写带下划线的「ID」去赌它在四处都能用。

> **收藏夹只能引用公开的。** 私密收藏夹**根本没有对外 ID**（不是「有 ID 但不显示」），
> 所以它既没有可写的 `[@ID]`，也生成不出二维码、读不到机器人接口。详见
> [收藏夹使用指南](收藏夹使用指南.md)。

表情包那一行是**另一套语法**：它不是 ID 而是「合集名 / 表情名」两个名字，允许中文，
用斜杠分隔。两种语法不会互相误伤 —— ID 只认字母数字，而表情 token 必含斜杠。

> 想**展示这个语法本身**（而不是让它生效）？把它写进代码块或行内代码（`` `[@a1b2c3d4]` ``）——
> 博客 / 云剪贴板正文与讨论里的引用都遵守「代码 / 链接里不展开」。**评论的 8 位剪贴板是
> 唯一例外**：它的展开发生在渲染前的原文扫描（`useResolvedContent`），写在评论代码块里仍会
> 被内联（已知限制，与 c 域 R3-135 同根因）。要展示 8 位剪贴板语法，别依赖评论的代码块。
> 反过来也成立：**ID 打错、或引用的内容不存在时，看到的也是原文那串字符**，不会报错、也不会
> 弹出提示 —— 所以文章里出现一句光秃秃的 `[@a1b2c3d4]`，先核对那串 ID。

## 三、四处地方，支持的不一样

| | 6 位收藏夹 | 8 位剪贴板 | 9 位投票 | 10 位图床图片 | `[@音频/<ID>]` | 表情包 | 用户名片 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 博客正文 | ✅ 最多 3 张 | ✅ 全部内联 | ✅ | ✅ | ✅ 最多 3 个 | ❌ | ❌ |
| 云剪贴板正文 | ✅ 最多 3 张 | ✅ 全部内联 | ✅ | ✅ | ✅ 最多 3 个 | ❌ | ❌ |
| **评论区** | ❌ 不展开 | ✅ 最多 1 条（仅 Markdown） | ❌ 不展开 | ✅ 最多 50 张 | ✅ 最多 3 个 | ✅ 最多 30 个 | ✅ 最多 5 张 |
| **讨论区** | ❌ 不展开 | ✅ 最多 1 条（Markdown 与 ReactiveMD） | ❌ 不展开 | ✅ 最多 50 张 | ✅ 最多 3 个 | ✅ 最多 30 个 | ✅ 最多 5 张 |

上表为成员视图。访客或无成员资格账号阅读对外博客时，图床图片、音频依各自公开规则展示；
所有剪贴板、投票与收藏夹保留引用原文，不携带正文或元数据。文章公开不会扩大剪贴板的受众。

评论与讨论里**刻意不支持投票**：投票是个可点选的交互组件，塞进讨论气泡和楼中楼里既挤又容易误触，要看投票请把链接贴出来。

评论与讨论里**也不展开收藏夹**，但理由不同：收藏夹卡片是一份**列表**（标题 + 若干文章链接），
塞进讨论气泡里会占掉半屏，而且讨论区没有「一篇正文慢慢读」的语境。所以在评论区与讨论区里
`[@123456]` 原样显示为字面量 —— 与投票同样是刻意的，不是漏了。

**收藏夹在博客里也另有更紧的上限：最多 3 张卡片。** 卡片是**块级**元素，比一段文字高得多，
插十几张会把文章冲成一片卡片墙；扫描出的第 4 张起原样保留 `[@123456]` 字面量。
收藏夹属于「需要取数」的一类，因此也占用上面那 50 个取数名额。

评论区里引用的剪贴板如果是 **ReactiveMD** 剪贴板，只给一条站内链接（而不是整段正文）；
讨论消息由聊天专用 RMD 适配器处理，Markdown 与 ReactiveMD 剪贴板都内联正文。见本文第四节。

**表情包**（`[@合集/表情]`）反过来 —— **只在评论与讨论里能用**，博客正文与剪贴板正文里
原样显示。它走的是另一套语法的形状（不是 ID 而是名字），详见
[表情包使用指南](表情包使用指南.md)。

**用户名片**（`[@用户/<用户名>]`）与表情同向 —— **也只在评论与讨论里能用**，而且同样
不是 ID 而是名字。它渲染成一枚行内名片（带头像框的小头像 + 用户名），点进那个人的主页，
见本文第七节。

另外两处细节差异：

- **剪贴板引用**在博客里可以写很多条；在评论 / 讨论里**一条消息只展开第一条**，多写的那些原样留在正文里（`[@abc12345]` 就那么显示着）。这是刻意的上限，避免一条 10 个字的短消息展开成几十万字。
- **剪贴板正文超过 2000 字**时，在评论 / 讨论里会被截断，后面接一句「内容过长，已截断」和回原剪贴板的链接。博客正文里不截断。
- **上限是「处数」和「取数名额」，不是整篇字数**：博客 / 云剪贴板正文最多替换 **50 处**引用（剪贴板、投票、图床共用这份额度），其中需要取数的引用一轮最多取 **50 个不同 ID**；单条剪贴板正文本身上限 5 万字。超出的引用**原样保留** `[@…]`，单条引用不会被从中间截断。
- **剪贴板引用不会再展开**：从剪贴板带进来的正文里若又写了 `[@8位]`、投票或收藏夹，那一层原样显示，不会继续挖下去（免得两条互相引用的剪贴板来回放大）。图床与音频只拼地址、不取数，不受这条限制。

### 站外读者看到的引用（文章对外公开时）

文章可以设为「对外可见」（见 `docs/agent-domain-rules.md` §2.19），站外读者**没有账号**。
图床图片与音频由浏览器读取 raw 地址，私有资源依原规则返回 404。
剪贴板、投票与收藏夹均保留字面量，不读取、不下发标题、正文或版本；
共享、私密、缺失和已删除剪贴板在此视图中同形。

**所以**：如果你打算把一篇文章对外公开，并且希望站外读者也能看懂，
别把关键信息放在投票 / 收藏夹 / 剪贴板的引用里 —— 用普通的文字或图片写出来。

### 统一渲染器下的引用（2026-11 起）

博客详情与剪贴板详情**默认全部**走 ReactiveMD 统一渲染器（不再按百分比灰度）。
引用语义按内容类型与查看者权限决定：

| 引用 | 成员阅读（core+） | 站外 / 非成员视图 |
|---|---|---|
| 图床 `[@10位]` | 内联图片，点开放大 | 内联图片（浏览器直接取 raw 地址） |
| 音频 `[@音频/ID]` | 内联播放器 | 内联播放器 |
| 投票 `[@9位]` | 可交互投票 | 保留 `[@9位]` 字面量，不发请求 |
| 收藏夹 `[@6位]` | 收藏夹卡片 | 保留 `[@6位]` 字面量，不发请求 |
| 剪贴板 `[@8位]` | 内联正文（Markdown 与 ReactiveMD 一样，不套卡片） | 保留字面量，不读取资源 |

- **一律内联正文，不按格式分流**：被引用的剪贴板是 Markdown 还是 ReactiveMD 都不影响结果；
  父文档是哪种也一样 —— 同一篇正文保存前后的阅读结果不会变。
- **子正文只展开这一层**：内联进来的正文里若还有 `[@8位]`、投票或收藏夹，那一层按字面量显示，
  不再递归取数；它的 `{{ }}` 也不会进入父文档的绑定作用域。图床与音频只拼地址，仍会正常显示。
- **没有外壳**：子正文直接排进正文流（同一套字号、行高、段距），不是卡片、不是带底色的方块，
  也没有「查看剪贴板」的回链。
- **评论 / 讨论是另一条管线**：那边只内联 Markdown 剪贴板，ReactiveMD 剪贴板给一条站内链接
  —— 它们不跑正文这条 ReactiveMD 引用适配，见本文第四节末尾。
- **站外视图零业务请求**：图床与音频由浏览器取 raw 地址；剪贴板、投票与收藏夹保留原文。
  文章公开**不会**扩大剪贴板的受众：私有剪贴板对站外读者仍然只是一个字面 token。
- 预算与失败口径不变：50 处主引用、收藏夹 3 张、音频 3 个、50 次取数、4 并发；
  单处失败只影响那一处，不波及其余正文。

## 四、剪贴板嵌入（8 位 ID）

### 获取 ID

访问 `/clipboard/`，在列表中查看每个剪贴板的 8 位 ID，或从剪贴板详情页 URL `/clipboard/<ID>` 中获取。

### 使用方式

在正文中直接写入：

```
[@a1b2c3d4]
```

### 渲染行为

系统按 `[@a1b2c3d4]` 取回那段剪贴板正文，把它的**内容**排进你的文章（标题、列表、代码块、
公式、组件都与原文一致），位置就是 token 所在处。子正文是独立编译的，不会把它的变量带进
你的文章作用域；它自己再写的剪贴板 / 投票 / 收藏夹引用保持字面量。

> ⚠️ 精确口径：成员视图里**一律内联内容**，与剪贴板是 Markdown 还是 ReactiveMD 无关，
> 也不套卡片或外壳；对外 / 访客视图（external）里所有剪贴板 token 一律保留字面量，不取正文。
> 评论 / 讨论只内联 Markdown 剪贴板，ReactiveMD 剪贴板给站内链接。
> 见「三、四处地方，支持的不一样」。

### 错误处理

博客 / 云剪贴板正文里，引用取不到或没有读取权限时，那个位置显示一块**不可点的占位**：
取数失败是「内容加载失败」，无权限是「无权查看此内容」。评论 / 讨论里则是一句
`[剪贴板 a1b2c3d4 加载失败]`。

> 在站内这**不算异常**：剪贴板接口要求登录且 Core 以上。你自己预览时若也只看到占位，
> 先确认登录状态与被引用剪贴板的公开设置（私密剪贴板只有作者本人能展开）。

## 五、投票嵌入（9 位 ID）

> ⚠️ **只在博客正文与云剪贴板正文里生效。** 评论区和讨论区不展开投票，`[@vOtE12345]` 会原样显示。

### 获取 ID

访问 `/vote/` 查看**你自己创建的**投票列表（最新在前），或从投票详情页 URL `/vote/<ID>` 中获取。

列表只含你自己创建的投票。要打开别人的投票，用 `/vote/` 顶部那栏「搜索跳转」：输入 ID 后点「前往」。

### 使用方式

```
[@vOtE12345]
```

### 渲染行为

系统请求投票数据并在文章内渲染一个**投票小组件**，形态随你的投票状态而变：

- **你还没投过、且投票未锁定**：显示标题 + 可点击的选项 + 「投票」按钮，在文章里直接投票，无需离开本页。
- **你已投过票、或投票已被发起者锁定**：显示结果视图 —— 每个选项的票数、百分比与进度条，顶部显示"共 X 票"，你投过的那项带 ✓ 高亮。
- 无论哪种状态，组件底部都有「查看详情」，新窗口打开投票详情页 `/vote/<ID>`。

投票后组件会重新拉取服务端的票数并就地刷新。

### 错误处理

如果投票数据加载失败，该位置会显示：`[查看投票]`（可点击跳转到投票页）

## 六、图床图片嵌入（10 位 ID）

### 获取 ID

访问 `/image/` 查看你上传的图片列表，或在图片详情中获取 10 位 ID。

### 使用方式

```
[@AbCdEf1234]
```

### 渲染行为

系统把它换成图片地址 `/api/images/AbCdEf1234/raw`，四处都是这个地址。图片渲染后支持点击原地放大（不新开窗口）。

### 说明

图片嵌入不需要额外请求 API —— 系统直接拼接图片 URL，浏览器加载时自然请求 `/api/images/<ID>/raw`。如果 ID 对应图片不存在或已被删除，会显示为损坏图片。

⚠️ **供其他成员阅读的内容应引用公开图片。** 私有图片会校验读取权限，没有读取权限的读者无法加载图片 —— 这一点在四处都一样。

**评论 / 讨论里发图还有一条更省事的路**：点输入区的「从图床选择」，直接弹出你自己的图片列表挑一张，不用去翻 ID、也不用重新上传。

> 评论与讨论里**手写 `<img>` 标签是显示不出图片的**（会被当成普通文字）。能出来的图片只有
> `[@10位ID]` 这一种形态 —— 这是防止有人贴外链图做跟踪像素。博客正文里手写 `<img>` 则允许。

## 七、用户名片嵌入（`[@用户/<用户名>]`）

> ⚠️ **只在评论区与讨论区生效。** 博客正文与剪贴板正文里 `[@用户/张三]` 原样显示字面量。

在正文里写一个人的**用户名**，渲染出来是一枚**行内名片**：带头像（含头像框）的小头像
+ 用户名，点一下进他的主页。

```
[@用户/张三]
```

**这一条与其他引用都不一样：它认的是名字，不是 ID** —— 你不用去翻谁的主页地址栏。
用户名在本站**不可修改**（注册之后没有任何改名的入口），所以今天写的名片明天还指得准。

### 怎么插入

评论区与讨论区的输入区工具栏上有一颗名片按钮：点开 → 搜用户名 → 选一个人，
token 就落在光标处。**不会**替你发送（草稿还在，接着写完再发），也不会多带空格。

**手打一样有效** —— 上面那行直接敲进去就行。

### 规则

- **一条消息最多 5 张名片**，多出来的原样显示为 `[@用户/…]`。
- **名字打错 / 查无此人 → 原样显示字面量**（不报错、不留半张卡）。所以看到原文 token
  就是「这个人没找到」，不是页面坏了。
- **只认核心用户**：输入区那个选择器搜得到的人是 core 及以上；非核心账号仍可以
  **手打** token 发名片，只是选择器搜不到。
- **不算 @ 提及**：对方**不会**收到通知，铃铛与讨论红点都不动。想叫他就照常写 `@张三 `。
- **写在代码块 / 行内代码里的不展开**（与其余引用一致）—— 想展示这个语法本身就这么写。
- 名片里的头像是**站内那条恒定可推导的地址**，所以「没上传过头像」的人也会有一张
  （系统生成的图案），不会是裂图。

### 与表情的「用户」合集

`[@用户/张三]` 与表情 `[@合集/表情]` 形状完全一样，所以 **`用户` 这个名字归名片** ——
站长的表情合集不能叫「用户」（那个目录会被扫盘跳过）。见
`docs/guide/表情包使用指南.md`。

## 八、注意事项

1. **非用户提及**：`[@ ]` 语法不是 @用户 功能，不能用来提及或通知其他用户。
2. **数量限制**：显示上限分三档 —— 主循环最多替换 **50 处**（剪贴板 / 投票 / 图床图片共用）、**收藏夹最多 3 张**、**音频最多 3 个**；取数上限是**需要取数的剪贴板 / 投票 / 收藏夹一轮最多 50 个**（图床图片与音频只拼地址、不占这个额度）；单条剪贴板正文最多 5 万字。超出的引用一律保留原文；其中**没排进取数候选**的连请求都不发。评论 / 讨论里剪贴板最多 1 条、图片最多 50 张；讨论另有音频最多 3 个、表情与黄脸合计 30 个、名片最多 5 个的上限（评论沿用旧管线的对应上限）。
3. **权限检查**：私有剪贴板只有作者本人可以在文章中引用；其他人引用会加载失败。图片同理 —— 私有图对别人是裂图。
4. **ID 大小写**：ID 区分大小写（包含大小写字母和数字），请完整复制。
5. **编辑器里就能预览**：写博客 / 剪贴板时右栏（窄屏是「预览」那一档）看到的就是展开后的样子 —— Markdown 文档与发布后的详情页用的是同一台渲染器；reactive 文档的预览在浏览器里编译（与阅读页同一套编译选项和引用适配规则），不把源码交给 Markdown 管线。两条例外：`[@表情]` 与 `[@用户/…]` 只在讨论区和评论区生效，正文里它们始终是普通文字（博客不支持这两类）。
   **预览是只读的**：投票摆在那里但点不动，预览期间不会提交任何东西。写正文时也不需要手打 token —— 工具栏的「插入引用」面板可以挑一条直接插进来（图床 / 音频 / 剪贴板 / 投票 / 收藏夹），插进去的语法与手写完全一致。
6. **剪贴板内容是独立子文档**：它不与你的文章共用变量作用域，也不是把源码拼进你的 Markdown —— 那条剪贴板自己编不出来时只有那一处显示占位，不会把你的文章一起弄坏。
7. **代码块里不展开**：博客、云剪贴板、讨论都一样 —— 想展示语法本身，就写进代码块或行内代码。评论的 8 位剪贴板是历史例外（见上文）。
8. **剪贴板引用不递归**：从剪贴板带进来的正文里若又写了 `[@8位]`、投票或收藏夹，那一层不会再展开、原样显示 —— 免得两条互相引用的剪贴板来回放大。剪贴板引用自己、或两条剪贴板互相引用，都只展开一层。图床与音频只拼地址、不取数，不在这条之列。
