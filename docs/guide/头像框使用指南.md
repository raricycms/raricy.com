# 头像框使用指南

头像框是叠在你头像上的一圈装饰，会出现在**顶栏、评论区、讨论区、博客列表**和
你的**个人主页**上。

框是**站长发放**的，不需要你申请，也不能自己上传。你要做的就是决定戴不戴。

---

## 一、我有哪些框

打开 **账号设置 → 头像框**（`/settings#avatar-frame`）。

那一页分两块：

- **当前装备**：你现在戴的那个，右边有一颗「摘下」。
- **我持有的框**：你手上所有的框，每个右边有一颗「戴上」。

点一下就生效，不用保存。**戴上之后顶栏的头像会立刻变**，不用刷新页面。

> 个人主页右上角也有一顆「换个头像框」，点了直接跳到那一页。

---

## 二、限时的框到期会怎样

有些框是**限时**的（站长发放时定的），比如「中秋活动」那一款只发 30 天。

到期后：

- 框会**自动消失**，你什么都不用做。
- 那一行还会留在列表里，标着「已过期」，但「戴上」按钮是灰的。
- 想让站长续期，找站长说一声 —— 续上之后框会**立刻回来**，不需要你重新戴。

**「已过期」和「已下架」是两回事**：

| 标记 | 什么意思 | 你能做什么 |
|---|---|---|
| 已过期 | 期限到了 | 等站长续期 |
| 已下架 | 站长把这款框整个撤了，以后不再发 | 只能摘下，不能再戴 |
| 素材缺失 | 站长还没把图传到服务器 | 等站长补图 —— 补上就会自己出现，不用重新戴 |

---

## 三、常见问题

**戴上之后没看到框？**

先看清单里那一行有没有标「素材缺失」或「已过期」。两者都会让框显示不出来，
原因不一样（前者等站长补图，后者等站长续期），所以分开标。

**框会盖住我的头像吗？**

不会。框素材中间是**透明**的，露出下面的头像。如果你看到自己的脸被挡住，
那是站长传错了素材，跟他反馈一下。

**能同时戴好几个吗？**

不能，一次只有一个。换一个就是直接覆盖。

**摘下来之后还在吗？**

在。摘下只是「不戴」，框还是你的，随时可以再戴上。

**能自己上传一张图当框吗？**

不能，本站不接受上传头像框。框由站长统一出素材、统一发放。

## 四、给站长：怎么加一款新框

这一节是**运维向**的，普通用户看到这里就够了。

### 1. 出图规格

框是一张叠在头像上的 PNG，**中间必须透明**。几条硬要求：

- **正方形**。规格是「画布就是框」——所有头像都是方的（20 / 24 / 32 / 34 / 120px
  六档），非正方形的素材会被**留白**（不会被拉伸，但会小一圈）。
- **带透明通道**（PNG-32）。没有 alpha 的素材会**盖住所有人的脸** ——
  那是全站 15 处一起坏，而且你可能只在自己的主页看一眼。
  导出时别「压平 / flatten」。
- **建议 ≥ 256×256**。它会缩到 20px（博客列表的作者头像）——太细的线条
  （<1.5px）在那个尺寸下会糊成一片。画完**缩到 20px 看一眼**再定稿。
- **越界的部分会被裁掉**。框画布之外的东西（伸出去的翅膀、超出边界的王冠）
  不会显示 —— 头像盒子自带 `overflow: hidden`。
- 深浅两个主题各看一眼。框是不透明的图案，底色对比在深色主题下可能不够。

### 2. 放素材

把文件拷成 `instance/frames/<key>.png`：

```
instance/frames/
  sakura.png      →  key 是 "sakura"
  laurel.png      →  key 是 "laurel"
```

- `<key>` 只能用小写字母、数字与连字符（它同时是 URL 里的一段）。
- **只认 `.png`**。`.PNG` 也认；`.jpg` / `.gif` / `.webp` / `.svg` 一律忽略。
- `.` 或 `_` 开头的文件会被跳过（编辑器临时文件、macOS 的资源叉）。
- 目录**是平铺的一层**，没有子目录。
- 素材**不入库**（`instance/` 是 gitignored 的运行时数据），部署时要手动同步到服务器。

### 3. 登记

在 `src/lib/frame-refs.ts` 的 `FRAMES` 里加一条：

```ts
export const FRAME_KEYS = ['sakura', 'laurel'] as const;

export const FRAMES: Record<FrameKey, FrameDef> = {
  sakura: { label: '樱花', description: '2026 春季限定。' },
  laurel: { label: '桂冠', description: '给最早的那批人。' },
};
```

`FRAMES` 是**穷尽**的 `Record`：加了 key 不补条目，`tsc` 当场报错。

**不需要数据库迁移** —— `user_frames.frame_key` 是文本，不是外键。

### 4. 发放

```bash
npm run cli -- frame grant <用户名> sakura --days 30 -r "2026 春季活动"
npm run cli -- frame grant <用户名> laurel          # 不带 --days = 永久
```

细节见 `docs/cli.md` 的「头像框」一节。

### 5. 自查（★ 别跳过这一步）

```bash
npm run cli -- frame list --keys
```

它会列出白名单里**每一个** key 的素材状态：

```
sakura   樱花   素材:有   透明通道:有   18244 字节
laurel   桂冠   素材:缺失   透明通道:—   — 字节
```

**这是唯一能主动发现「登记了但忘了传图」的地方。** 那种情况下全站都不会显示
这个框，而**页面不会有任何报错** —— 用户那边看起来跟「我没这个框」一模一样。

`透明通道:无` 也要处理：那张素材会盖住用户的脸。

### 6. 下架一款框

把 `FRAMES` 里那条加上 `retired: true`：

```ts
sakura: { label: '樱花', description: '…', retired: true },
```

⚠️ **不要从 `FRAME_KEYS` 里删掉 key。** 删了之后系统就认不出它了 ——
设置面板显示不出那一行，**还戴着它的用户会摘不掉**（只能看它一直挂在头上）。
置 `retired` 则：列表里还看得见、标着「已下架」、能摘不能戴。

### 7. 改价格 / 加购买

第一版没有购买路径（框只能由站长发）。加鱼干购买**不用改表** ——
`user_frames.source` 已经预留了 `'purchase'` 这个值来区分「买的」与「发的」。
