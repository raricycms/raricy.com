# 全站前端文案与信息架构审计

> 校对日期：2026-10-30。源码基线：`6617c4fb`。状态：**调研与产品设计已整理，重构未实施**。
> 页面、路由与产品规则均为目标设计；本轮只更新计划，当前功能、权限与对外接口尚未改变。

## 1. 结论与判断标准

最需要重构的是**页面职责和信息出现的时机**。目前不少入口按照功能增加的顺序堆放，
再用文字解释它们的用途、限制与例外，用户因而要先理解系统，再完成眼前的操作。

问题最集中在小鱼干与每日一言。前者混合账户、转账、消费、练手盘和开发接入；
后者借签到取得入口，却在签到、收藏夹两棵路由树之间切换。共用输入组件则把快捷键、
字数限制和 Markdown 能力累加为常驻说明，将重复扩散到了评论和讨论。

本轮登记 **50 项问题与结构建议**：12 项 IA、5 项流程与状态、6 项错误或误导表达、27 项文案负担。
条目是后续任务的拆分单位，部分共享成因，不代表 50 个独立功能故障。
搜索范围、收藏夹受众和注册资格的不一致应先解决；处理方向由目标产品规则决定，不能默认以当前实现迁就文案。
新增产品设计见 §8.4–§8.7：邀请码必填、成员模型、剪贴板站内共享和公开正文搜索。

判断每段文字时先问：**它能否帮助用户在此刻选择、避免损失、理解状态或找到下一步？**

| 信息类型 | 默认处理 |
|---|---|
| 名称、字段标签、有效搜索占位符 | 保留，必须对应真实对象和能力 |
| 工具短介绍、合适空态、品牌表达 | 可以保留，不因“不是操作必需”就删除 |
| 已由控件与结果表达的规则 | 去除重复，用选中、禁用和真实结果表达 |
| 低概率触发的字数/次数上限 | 接近上限或触及时提示 |
| 可选能力和完整操作方法 | 工具条、按需帮助、指南承接 |
| 扣费、公开范围、匿名边界、不可撤回、转换损失 | 选择或确认前说明，不能一律拖到操作后 |
| 服务器配置和实现过程 | 进入日志或开发者界面，普通页面给出可执行的下一步 |

优先级：**P1** 是错误承诺或主要任务归属；**P2** 是常用页面的重复与流程负担；
**P3** 是低频、较轻的表达整理。这是依据源码的风险排序，未用访问量或转化率排序。

候选包括错误反馈、元数据、可访问名称，不能直接当成首屏可见文案计数。
逐模块复核入口、返回路径、共用组件和状态分支，并对照相关服务端查询核实文案承诺；

这是**源码审计**，未完成逐页浏览器截图、真实设备验收、访谈或行为数据分析。
“常驻”指相应源码分支持续渲染，实际视觉权重仍需页面验收；未假定线上版本等于本地源码。
用户文章、小说、投稿正文不属于界面文案；协议、隐私政策和接口文档未做逐字法律或协议审查。

### 8.4 邀请注册与成员模型

本节及后续三节根据产品讨论补充目标规则，尚未实施。§5 的 TR-01、TR-03、TR-04
应按目标调整功能，不能仅修改文案来迁就现状；TR-02 则统一成员分享的名称和受众。

**目标：公开注册必须填写有效邀请码，注册成功直接成为成员（core）。**
界面常用“成员”，内部继续保留 core / admin / owner 角色键；管理员、站长属于成员以上档位。

| 身份或状态 | 产品职责 |
|---|---|
| 访客 | 阅读对外内容、搜索对外公开文章、使用原本无需账号的公共功能 |
| 成员（core+） | 站内创作、互动、受控资源管理与日常鱼干功能；管理员和站长另有管理权限 |
| 历史未认证账号、被取消成员资格的账号 | 保留补码认证、账号安全和必要历史资产处置，不再设计成常规注册后的产品档位 |

“站内操作收束 core+”适用于上述成员业务。登录、注册、申请邀请码、公开阅读与搜索仍需可达；
现有公开故事、公共工具等也不因此自动加成员门槛。禁言、取消成员资格、账号归档分别按自身规则处理，
不能将禁言扩展为不能止损或不能管理账号安全。

**注册和资格流程**

1. 注册页提供用户名、邮箱、密码和必填邀请码；移除“可选”“之后再填写”等引导。
2. 没有邀请码时给清楚的申请入口，直接通往现有联系/申请流程；资格页统一讲如何获得邀请。
3. 服务端拒绝缺省、空串、纯空白、无效或已用邀请码，不仅添加前端 required 属性。
4. 校验通过后，创建 core 账号与原子占用邀请码处于同一事务；失败不留半成品账号，也不消耗邀请码。
   同一个一次性邀请码的并发注册最多成功一次，沿用现有防竞态机制。
5. 完成注册后建立会话，沿用既有安全返回地址机制；不插入第二次“认证成功”步骤。
6. 站长授权建号与运维建号按既有入口和权限独立处理。不要把公开注册的邀请码要求塞进共用建号内核，
   从而错误限制 CLI、管理功能或测试种子建号。

**已有账号与资格变更**

- 不批量提升现存 user 账号，也不删除其资料。历史未认证账号登录后可通过原认证入口补码取得成员资格。
- 取消成员资格仍须即时撤销成员业务权限；保留 user 角色或等效的“未取得/已撤销资格”状态，
  不因前端身份模型简化而删掉服务端鉴权。
- 历史余额、流水和未结仓位不能随资格变化失去查询与退出路径。保留必要的只读、转出及平仓处置，
  同时拒绝无资格账号新增赚取、开仓、购买和内容互动。实施时为这些处置动作单独列权限用例，
  不把它们变成另一套可正常使用全部功能的普通用户产品。
- 本轮不调整鱼干计价、收益、手续费、账本或权限管理者的分工。资格变更的会话及实时连接处理
  沿用认证体系要求，页面和 API 都检查当前资格。

实现落点：`src/app/register/page.tsx`、`src/app/api/auth/register/route.ts`、
`src/lib/user-service.ts`、认证/资格页面、角色校验与管理端；
盘点所有仅检查“已登录”的成员业务入口及 API，不能只改注册页就认为权限已经收束。
公开注册的接口契约会改变，实施时同步注册说明、接口文档和相关测试。

### 8.5 剪贴板：站内共享，不随公开文章向访客展开

**目标：剪贴板是站内可复用资源，文章公开不扩大被引用剪贴板的受众。**
剪贴板保留“私密”和“站内共享”两档，首期不新增对外公开档，也不默认复制引用内容进文章。
现有 publicity=true 对应“站内共享”，false 对应“私密”；不为名称调整改写已有内容或生成新 ID。

| 查看场景 | 目标行为 |
|---|---|
| core+ 查看站内共享剪贴板或其引用 | 按既有格式和引用能力展示 |
| 本人或站长查看私密剪贴板 | 沿用既有授权，不扩大到其他成员 |
| 其他成员查看私密引用 | 沿用权限限制，不因文章作者或文章公开状态而放行 |
| 访客或无成员资格账号查看公开/凭链接可读博客 | 所有剪贴板引用保留字面量，例如 [@AbCd1234]，不展开正文或生成带标题的链接卡片 |

未取得资格的账号按访客规则读取对外文章。私密、共享、已删除、不存在的引用在该视图中同形，
不能从标题、错误类型或占位差异判断资源是否存在。代码块和行内代码里的引用继续按代码处理。

**所有渲染路径统一执行**

- 旧 Markdown 路径停止为对外文章调用公开剪贴板解析；不向 RSC/HTML/客户端属性下发剪贴板正文、标题或版本。
- Reactive 预处理、引用读口、链接卡片、静态快照与回退路径遵循同一规则；
  external 模式不读取剪贴板。不能只是前端藏正文，却继续把数据放进页面载荷。
- 检查持久快照和渲染缓存的引用权限重验、编译签名与失效机制。旧快照可能已经含引用标题或元数据，
  发布切换必须使这些结果失效或重新生成，不能把旧卡片继续用于访客视图。
- 剪贴板独立页、API 和其他引用消费者继续按各自成员/所有权规则授权。
  不放宽独立读口来修复旧访客卡片，也不误改站内机器人命名空间。
- 博客自身保留的对外图片、音频等资源维持各自公开规则；本决策不自动改变它们的访问范围。

**编辑与发布体验**

剪贴板表单和工具入口统一用“站内共享/私密”，移除“能被公开博客带到站外”的旧说明。
作者若要对外展示其中的文字，应将所需内容明确写入公开文章；该文字随后作为文章正文维护，
不会继续跟随站内片段更新。公开前的访客预览须与最终访客视图一致，
引用规则说明放在首次需要理解它的编辑/发布场景，不在每张阅读卡片常驻重复。

已经向外展示或被保存的内容不能靠此变更收回，因此只承诺切换后的读取行为，
不使用“绝不会被搜索引擎找到”之类表述。

实现落点：`src/app/blog/[id]/page.tsx`、`src/lib/clipboard-service.ts`、
`src/lib/content-ref-resolver.ts`、`src/lib/reactive/prepare.ts`、
`src/lib/reactive/ref-adapter.ts`、`src/lib/reactive/ref-reader.ts`、
`src/lib/reactive/read-render.ts`、`src/lib/reactive/snapshot-store.ts` 与引用组件。
更新时同步架构、剪贴板/引用指南及当前仍要求“公开剪贴板可对外展开”的仓库指引和测试；
本计划记录目标，本轮不提前改写现行规范为已实现行为。

### 8.6 公开博客搜索：包含自身正文，受公开集合约束

**目标：访客可按标题、简介、作者和文章自身正文查找对外公开文章。**
检索范围是 public 且未软删的文章；internal 和 link 都不进入公开搜索。
拿到 link 文章的地址能阅读，不代表可以通过全站搜索发现它。

**搜索体验**

- 保留一个搜索框，输入范围与占位符一致，不为补充正文搜索增加常驻教程或复杂字段开关。
- 正文命中提供适量的上下文片段，准确高亮匹配内容；没有关键词时回普通公开列表。
- 首期优先保证中文短语、单字/双字和英文关键词能按预期检索，不采用只对英文有效的分词结果。
- 结果按匹配相关性组织，并以发布时间、ID 等稳定字段处理并列结果，确保翻页不漂移；
  具体权重在实现选型时固定并纳入回归测试。
- 无匹配、请求过频和搜索暂不可用分别反馈；不能将限频或服务错误伪装为空结果。

**索引内容与权限**

1. 只索引文章自身可对外展示的文字，包括正常可见代码；不解析或收录站内剪贴板、投票、收藏夹、
   私密附件、评论或成员资料，不为搜索扩张资源的访问权限。
2. Markdown 和 Reactive 均按可读文字构建索引，过滤标记/组件实现、脚本、隐藏数据与资源引用 token。
   格式或编译失败时不要回退为索引原始 Reactive 源码；可继续检索标题等安全元数据，并记录正文索引缺失。
3. 索引只是候选来源。最终查询、计数、分页、片段生成和缓存返回都受当前 public 白名单及软删状态约束。
   内容转回站内、转为 link 或软删后，旧索引不能继续返回标题、命中片段、数量等可发现信息。
4. 创建、编辑、格式切换、可见性变更、删除/恢复均有索引更新路径；索引可重建，
   延迟更新时由最终权限过滤挡住旧候选，不能只靠后台清理兑现可见性。
5. 站内目录筛选和账号专注偏好不改变匿名公开集合；公开搜索与公开目录、sitemap 继续使用一致的公开判据。

**实现与发布约束**

现有不搜正文的规则来自匿名请求扫描长正文的成本取舍。增加正文能力时应建立适合本站内容的索引，
而非仅向原元数据查询添加全文包含扫描。索引技术尚未选定；实施时以本站中文内容、
Markdown/Reactive 格式和近似生产规模验证支持范围、延迟及并发预算，记录可复现的性能数据后确定方案。
采用带数据的索引迁移时，按仓库手写迁移与一次性执行规则处理。

沿用公开搜索的服务端限频和输入约束，查询不执行用户内容，不绕过可见性过滤。
发布前完成历史 public 文章回填及一致性检查；索引未就绪时给明确的降级范围或暂不可用反馈，
不能一边宣称搜正文、一边静默只搜标题。

实现落点：`src/app/explore/page.tsx`、`src/app/blog/SearchForm.tsx`、
`src/lib/blog-service.ts`、`src/lib/blog-visibility.ts` 及后续索引实现。
同步更新现有禁止公开正文检索的类型、说明、行为测试和仓库指引，
保留公开集合白名单等仍成立的约束；站内检索与机器人接口不因本项自动改变契约。

### 8.7 收藏夹与可见范围词汇

邀请码必填后仍有访客，因此“任何人可见”不能等价为“任何成员可见”。
收藏夹保持站内整理与成员分享定位，本轮不扩大为匿名可读清单。

| 对象 | 用户侧名称 | 实际受众 |
|---|---|---|
| 文章收藏夹 | 私密 / 站内共享 | 本人 / core+ 成员；分享链接仍要求成员身份 |
| 剪贴板 | 私密 / 站内共享 | 本人与站长的既有授权 / core+ 成员；访客引用按 §8.5 保留原文 |
| 博客 | 仅站内 / 凭链接可读 / 对外公开 | core+ / 持有链接的访客也可读 / 访客可读且进入公开目录与搜索 |
| 一言收藏与保存消息 | 我的收藏 / 保存的消息，必要时简短标识私密 | 本人；不因成员模型调整而新增分享能力 |

收藏夹创建、导入、复制、详情、二维码、工具介绍和指南使用同一受众名称；
机器字段、公开句柄及所有权校验沿用当前契约，不为界面改名改变存储值。
成员未登录打开分享链接可走登录返回路径；已登录但资格不足时提供认证入口，
不能将其当成匿名可读资源。

§5 的处理归类随之明确：TR-01 调整搜索功能，TR-03 调整注册规则，
TR-04 调整引用访问边界并修订承诺，TR-02 统一成员分享表达；
TR-05 与 TR-06 仍属于直接修正文案/错误反馈。

## 9. 问题反复出现的成因

### 9.1 旧布局测试变成了新入口的选址约束

`src/app/fish/page.tsx:69`、`src/app/fish/market/page.tsx:68` 明确记载：
新入口放说明区或市场页脚，是为了不破坏“三颗按钮”的旧测试。
`tests/e2e/fish-layout.spec.ts:41`、`:69` 固定数量，
`tests/e2e/fish-market.spec.ts:144` 用整页标题选择器验证旧标题。

这些测试原本守住手机同行、不截字等实际问题，但数量和旧结构后来影响了功能归属。
重构应保留可触达、不溢出、目的地正确和交易正确等要求，随新结构更新旧断言，
不能继续为了通过测试把入口塞到页脚。

文案也存在同类现象：`tests/e2e/daily-quote.spec.ts:591` 要求“每人每句限一次”可见。
新验收应验证已共鸣清楚、不重复扣费、刷新和多标签页状态一致，
而非永久保留某句规则。关键后果文案及有交互价值的布局测试继续保留。

### 9.2 共用组件只累加说明

RichComposer 的 hintExtra 被设计为追加在快捷键之前，调用方再塞字数限制。
新说明与旧说明不断叠加，缺少“正常输入不需要说明”的默认状态。
应区分占位引导、按需帮助、临近上限、校验错误和操作状态，不常驻空说明行。

### 9.3 一个词承担多个对象

“公开”在博客、收藏夹和剪贴板中的受众不同；“市场/商城”共用页面；
“上传/创建”混用于内容编辑。应先建立对象、受众、动作、导航的词汇表，
再改入口与文案。仅抽一个全局文案常量文件解决不了语义冲突。

## 10. 实施顺序与验收

### 10.1 建议分批

| 批次 | 范围 | 验收重点 |
|---|---|---|
| 1：成员与引用边界 | TR-03、TR-04；§8.4、§8.5；旧账号过渡与快照/缓存处理 | 注册直接建 core，旧账号不被自动提权；访客无片段数据，成员引用仍有效 |
| 2：公开检索与表达 | TR-01、TR-02、TR-05、TR-06；§8.6、§8.7；CP-01–CP-08 | 正文搜索及权限过滤有效；成员分享词汇一致；输入无重复说明，付费动作预先标价 |
| 3：小鱼干结构 | 账户、转账、商城、练手盘导航和记录、外观跳转 | 与成员模型衔接，历史资产可退出；任务直接可找，余额一致，旧链可用 |
| 4：签到与一言分域 | 一言主页、统一导航、往期/收藏/投稿兼容 | 一次签到结果、稳定归属，沿用博客/签到门槛和历史数据 |
| 5：全站扫尾 | 设置分组、剪贴板、收藏复制、工具/文档/低频表达 | 只呈现当前所需信息，帮助可达，必要告知和可访问名称不丢失 |

按模块拆提交。§8.4–§8.7 是本计划明确列出的规则变化，与前端结构重构分别落地；
其余路由、文案和布局调整不顺带改变鱼干计价、余额算法、未涉及的权限或接口契约。

### 10.2 浏览器验收矩阵

每个改动模块覆盖桌面与手机，以及状态和操作路径：

- 访客、新注册成员、历史未认证/被取消资格账号、管理账号；按 §8.4 验证过渡及权限，保留专注策略。
- 签到前/后、未发博客/全部删除；一言可用/下架、免费/付费、未共鸣/已共鸣、余额不足、投稿被拒。
- 空输入、输入中、回复、附件、临近上限、超限、发送失败；手机键盘和中文 IME。
- 商城未持有/持有/到期、租用/续期、转账前后、页面切换后的余额与装饰状态。
- 收藏夹公开/私密、本人/分享接收者、空/非空；复制后两份独立。
- 旧深链、分页参数、刷新、前进后退、专注屏蔽；新旧入口都到正确任务。
- 键盘聚焦、读屏名称、字段标签；不依赖悬停才能理解关键选择。

成功标准：

1. 用户不读帮助也能从入口名判断目的地，找到转账、租装饰、交易记录、往期一言和投稿。
2. 同一状态在同一视图只说明一次，正常输入没有规则段，异常时反馈准确且可执行。
3. 费用与公开范围在决定前可见，默认规则与实现过程退出常驻阅读区。
4. 子页有稳定归属和返回路径，去重不破坏快捷任务和旧链接。
5. “文字变少”不是独立验收结果，实际任务路径和状态正确性才是。

仍待原型与实机验证：账户首页的具体分组、手机设置导航、一言主页与签到弹窗衔接、
实验合集的用户认知、不同等级账号对入口的理解。
独立文案去重可以先行；涉及注册、引用与搜索的条目按 §8.4–§8.7 同步调整功能与说明，不能继续只按旧行为改文案。

### 10.4 迁移与文档收口

- 邀请注册先保证服务端强制校验与原子建号，再切前端引导；保留旧认证入口和历史账号过渡。

  访客文章不再携带片段数据。其他机器人接口不因本轮计划自动扩权、改地址或改变字段含义。
