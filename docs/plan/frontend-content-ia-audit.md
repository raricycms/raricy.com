# 全站前端文案与信息架构审计

> 校对日期：2026-10-30。源码基线：`6617c4fb`。状态：**调研完成，重构未实施**。
> 下文建议的页面、路由和布局尚未实施；不能据此认为现有产品已经完成适配。

## 1. 结论与判断标准

最需要重构的是**页面职责和信息出现的时机**。目前不少入口按照功能增加的顺序堆放，
再用文字解释它们的用途、限制与例外，用户因而要先理解系统，再完成眼前的操作。

问题最集中在小鱼干与每日一言。前者混合账户、转账、消费、练手盘和开发接入；
后者借签到取得入口，却在签到、收藏夹两棵路由树之间切换。共用输入组件则把快捷键、
字数限制和 Markdown 能力累加为常驻说明，将重复扩散到了评论和讨论。

本轮登记 **50 项问题与结构建议**：12 项 IA、5 项流程与状态、6 项错误或误导表达、27 项文案负担。
条目是后续任务的拆分单位，部分共享成因，不代表 50 个独立功能故障。
搜索范围、收藏夹受众和注册资格的错误承诺应先纠正。

判断每段文字时先问：**它能否帮助用户在此刻选择、避免损失、理解状态或找到下一步？**

| 信息类型 | 默认处理 |
|---|---|
| 名称、字段标签、有效搜索占位符 | 保留，必须对应真实对象和能力 |
| 工具短介绍、合适空态、品牌表达 | 可以保留，不因“不是操作必需”就删除 |
| 已由控件与结果表达的规则 | 去除重复，用选中、禁用和真实结果表达 |
| 低概率触发的字数/次数上限 | 接近上限或触及时提示 |
| 可选能力和完整操作方法 | 工具条、按需帮助、指南承接 |
| 扣费、公开范围、匿名边界、不可撤回、转换损失 | 选择或确认前说明，不能一律拖到操作后 |
| 服务器配置和实现过程 | 进入日志或开发者界面，普通页面给出可执行的下一步 |

优先级：**P1** 是错误承诺或主要任务归属；**P2** 是常用页面的重复与流程负担；
**P3** 是低频、较轻的表达整理。这是依据源码的风险排序，未用访问量或转化率排序。

## 2. 调研范围与限制

清点了 `src/app` 的 **101 个 `page.tsx` 文件**；从该目录 **244 个 TSX 文件**提取中文 JSX、
字符串和模板字符串，共 3,535 条候选，再扫描 `src/games` 的 **33 个 TSX 文件**。
候选包括错误反馈、元数据、可访问名称，不能直接当成首屏可见文案计数。
逐模块复核入口、返回路径、共用组件和状态分支，并对照相关服务端查询核实文案承诺；
另查玩具清单、编辑器资源、几何工具的 **10 个 HTML 页面**、现有计划及相关端到端测试。

这是**源码审计**，未完成逐页浏览器截图、真实设备验收、访谈或行为数据分析。
“常驻”指相应源码分支持续渲染，实际视觉权重仍需页面验收；未假定线上版本等于本地源码。
用户文章、小说、投稿正文不属于界面文案；协议、隐私政策和接口文档未做逐字法律或协议审查。
证据为文件路径与一基行号，均对应基线，后续改动后行号可能移动。未修改既有未提交文件。

## 7. 应保留的正例与边界

本轮不建议把辅助文字统一删除。以下信息具有实际用途：

- **工具短介绍、搜索占位符、评论空态**：帮助辨认用途或找到下一步，不要求用户额外理解系统。
  首页“我们总将找到答案”属于品牌表达，也应与功能页冗余规则分开判断。
- **上传格式、大小与压缩损失**：`src/app/components/ImageUploader.tsx:110`、
  `src/app/components/AudioUploader.tsx:95`。文件大小和格式影响选择成本，比聊天的低概率字数上限更值得提前说明。
- **转换器的分层说明**：`src/app/tool/convert/ConverterApp.tsx:645` 已将格式与限制放进按需展开区。
  文件本地处理、转换损失、刷新会丢失未下载结果应保留。首次重组件加载可简化原因，但真实等待仍需反馈。
- **游戏的非直观规则和操作**：`src/games/hinge2/Hinge2.tsx:176`、
  `src/games/hinge3/Hinge3.tsx:128`、`src/games/lumen/Lumen.tsx:196` 的长规则受开关控制。
  长文不等于常驻，不能只靠关键词扫描就判为冗余。
- **支付/转账/租用后果**：收款人、金额、总租金、租期/到期、不可撤回、商户身份边界。
  编辑与确认分别服务输入和核对，不能因为两步都显示金额就认定为无用重复。
- **匿名、公开、授权、一次性密钥**：管理员可知匿名投稿者、公开内容可能被存档、第三方取得哪些资料、
  密钥仅显示一次，都应在决定前可见。
- **管理与教学页面的必要说明**：群发忽略通知偏好、禁用应用使令牌失效、验证码教学解释机制，
  服务于当前任务，不套用普通评论区的精简尺度。
- **权限、专注、通知语义**：不因去入口而改变 core+ 门槛；专注模式本人屏蔽的内容继续整体隐藏；
  不把讨论未读并进通知数；图标按钮的可访问名称继续保留。

已有事项不包装成新发现：剪贴板容器/标题归属和翻译入口取舍见
`docs/plan/maintenance-plan.md` §1/§2。翻译路由没有工具箱入口，但仍可直达，
不能据此认定为死功能并删除。文章收藏夹放在站务工具已有明确约定，本轮不按通用菜单惯例擅自迁回。

## 8. 建议的信息架构目标

### 8.1 小鱼干：按任务组织

```text
小鱼干 /fish
├─ 当前余额
├─ 转账 /fish/transfer                 建议新增
├─ 收款码                             保留现有生成与收款流程
├─ 流水 /fish/transactions
├─ 商城 /fish/shop                     建议独立
│  ├─ 头像框
│  └─ 聊天气泡
└─ 练手盘 /fish/trade
   ├─ 行情与持仓
   ├─ 交易记录
   └─ 统计 /fish/trade/stats

账号设置 → 开发者接入 → 鱼干接口 /fish/api
商城租用结果 → 使用/前往外观设置
```

账户操作和商城、练手盘分组，不必强压进同一排按钮；具体布局需桌面和手机原型验收。
“市场”当前没有独立、清楚的产品对象，建议退出用户侧命名。

旧市场页曾承担两个任务，不能无差别跳转后就认为语义兼容。
先更新站内入口，再为旧页保留任务选择或兼容壳，特别处理商品区深链。
URL hash 不发送给服务端，仅靠服务端跳转无法按旧 hash 区分商城意图。
既有支付、收款和对外 API 地址不随本轮展示重组改名。

拆页后仍须验证余额、确认、防连点、租期续接和装饰状态，不能用删说明替代状态正确性。
完整交易记录的入口及分页范围也应明确，不把最近结清列表伪装成完整历史。

### 8.2 每日一言：建立自己的功能域

```text
签到 /checkin
├─ 签到动作与一次结果
├─ 今日一言快捷查看
└─ 累计天数、签到榜

每日一言 /quotes                      建议新增
├─ 今日                               继续按现有签到资格开放
├─ 往期 /quotes/history
├─ 我的收藏 /quotes/saved
└─ 我的投稿 /quotes/submissions
   ├─ 投稿
   └─ 投稿记录、审核状态、按需展开修改历史
```

独立功能域不等于绕过角色、博客或签到门槛。今日区域未取得阅读资格时说明所需动作；
往期、收藏、投稿沿用各自服务端规则。签到成功打开一言的便利可保留，弹窗与主页复用阅读互动组件。

一言页面统一导航、当前项和返回目标。文章收藏夹可保留次级快捷入口，但不再充当唯一父级。
旧往期、投稿、一言集路径兼容，并保留分页参数、历史数据和浏览器前进后退行为。
路由拼写是建议；功能归属和任务路径一致比立即改 URL 更重要。

### 8.3 其他模块

- 讨论/评论共用输入区保留输入、附件/工具、评论匿名选择和提交，反馈跟随真实状态。
- 设置先分组和增加页内导航，不必立刻拆多个页面；外观与商城互相直达具体分类和设置段。
- 剪贴板统一名称、创建/编辑动作、唯一页标题；公开范围仍准确说明。
- 文档统一地址时保留内容来源单一和功能内帮助，不另写第二套正文。
- 玩具单独决定测试/实验合集边界，不扩大为全部游戏改玩法。
- 个人主页布置模式中的拖动/保存提示有具体用途，不应扩散到普通访客视图。

## 9. 问题反复出现的成因

### 9.1 旧布局测试变成了新入口的选址约束

`src/app/fish/page.tsx:69`、`src/app/fish/market/page.tsx:68` 明确记载：
新入口放说明区或市场页脚，是为了不破坏“三颗按钮”的旧测试。
`tests/e2e/fish-layout.spec.ts:41`、`:69` 固定数量，
`tests/e2e/fish-market.spec.ts:144` 用整页标题选择器验证旧标题。

这些测试原本守住手机同行、不截字等实际问题，但数量和旧结构后来影响了功能归属。
重构应保留可触达、不溢出、目的地正确和交易正确等要求，随新结构更新旧断言，
不能继续为了通过测试把入口塞到页脚。

文案也存在同类现象：`tests/e2e/daily-quote.spec.ts:591` 要求“每人每句限一次”可见。
新验收应验证已共鸣清楚、不重复扣费、刷新和多标签页状态一致，
而非永久保留某句规则。关键后果文案及有交互价值的布局测试继续保留。

### 9.2 共用组件只累加说明

RichComposer 的 hintExtra 被设计为追加在快捷键之前，调用方再塞字数限制。
新说明与旧说明不断叠加，缺少“正常输入不需要说明”的默认状态。
应区分占位引导、按需帮助、临近上限、校验错误和操作状态，不常驻空说明行。

### 9.3 一个词承担多个对象

“公开”在博客、收藏夹和剪贴板中的受众不同；“市场/商城”共用页面；
“上传/创建”混用于内容编辑。应先建立对象、受众、动作、导航的词汇表，
再改入口与文案。仅抽一个全局文案常量文件解决不了语义冲突。

## 10. 实施顺序与验收

### 10.1 建议分批

| 批次 | 范围 | 验收重点 |
|---|---|---|
| 1：承诺纠正与输入减负 | TR-01–TR-05；CP-01–CP-08；名词统一 | 搜索、可见范围、注册资格真实；输入无重复提示，限制有效，付费动作预先标价 |
| 2：小鱼干结构 | 账户、转账、商城、练手盘导航和记录、外观跳转 | 任务直接可找、商城不先经过转账、余额一致、旧链可用 |
| 3：签到与一言分域 | 一言主页、统一导航、往期/收藏/投稿兼容 | 一次签到结果、稳定归属、权限和历史数据不变 |
| 4：全站扫尾 | 设置分组、剪贴板、收藏复制、工具/文档/低频表达 | 只呈现当前所需信息，帮助可达，必要告知和可访问名称不丢失 |

按模块拆提交。路由、文案和布局调整不顺带改变鱼干规则、权限、余额算法或对外契约。

### 10.2 浏览器验收矩阵

每个改动模块覆盖桌面与手机，以及状态和操作路径：

- 未登录、普通账号、core+、管理账号；既有档位入口和专注策略保持。
- 签到前/后、未发博客/全部删除；一言可用/下架、免费/付费、未共鸣/已共鸣、余额不足、投稿被拒。
- 空输入、输入中、回复、附件、临近上限、超限、发送失败；手机键盘和中文 IME。
- 商城未持有/持有/到期、租用/续期、转账前后、页面切换后的余额与装饰状态。
- 收藏夹公开/私密、本人/分享接收者、空/非空；复制后两份独立。
- 旧深链、分页参数、刷新、前进后退、专注屏蔽；新旧入口都到正确任务。
- 键盘聚焦、读屏名称、字段标签；不依赖悬停才能理解关键选择。

成功标准：

1. 用户不读帮助也能从入口名判断目的地，找到转账、租装饰、交易记录、往期一言和投稿。
2. 同一状态在同一视图只说明一次，正常输入没有规则段，异常时反馈准确且可执行。
3. 费用与公开范围在决定前可见，默认规则与实现过程退出常驻阅读区。
4. 子页有稳定归属和返回路径，去重不破坏快捷任务和旧链接。
5. “文字变少”不是独立验收结果，实际任务路径和状态正确性才是。

仍待原型与实机验证：账户首页的具体分组、手机设置导航、一言主页与签到弹窗衔接、
实验合集的用户认知、不同等级账号对入口的理解。
这些待验证项不影响先纠正已证实的错误承诺和重复提示。
