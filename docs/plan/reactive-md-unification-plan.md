## 1. 产品目标与完成边界

### 1.1 最终使用方式

ReactiveMD 在本站的定位是：**兼容本站既有 Markdown 的增强文档语言与统一渲染引擎**。

- 普通作者直接写 Markdown；旧文章、旧剪贴板无需为了换引擎而重写。
- 有交互需求的作者在同一篇源码里混写 ReactiveMD 组件、表达式和普通正文。
- 博客与云剪贴板使用同一编辑器、同一套语法选项与兼容规则；预览与最终阅读一致。
- 正常阅读对全部目标正文启用新引擎，组件按其语义交互；首屏 SSR 与无 JavaScript 阅读
  仍有可读初始状态。作者发布了滑块，正常阅读页就能使用滑块。
- 作者界面移除 Markdown / ReactiveMD 手动格式选择，不增加强制的“开启增强语法”步骤。
- 工具栏以 **Insert、Components、上传图片、插入引用** 为四个主入口。

“全量”指目标入口全部切换，既含现有 Markdown 也含已声明 ReactiveMD 的正文。
百分比灰度、逐篇人工 override、长期自动退回旧渲染器，都不作为最终常规工作方式。

### 1.2 本轮覆盖与不扩张的范围

| 范围 | 本轮交付 |
|---|---|
| 博客 | 新建、编辑、草稿恢复、预览、成员及对外阅读、导出、摘要、公开搜索正文提取 |
| 云剪贴板 | 新建、编辑、手动保存、自动保存、草稿、预览、详情阅读、复制原文、导出及被引用时的格式分派 |
| 站内引用 | 图床、音频、剪贴板、投票、收藏夹；原有权限、预算与失败口径一致 |
| 共用编辑器 | 桌面与手机、工具栏、选区、撤销重做、快捷键、IME、上传、引用选择及诊断 |
| 外部契约 | 博客 / 剪贴板 API、spider、草稿格式、搜索索引和旧消费者能辨别增强源码 |
| 评论、讨论、故事、站内文档 | 继续使用各自现有正文管线；本轮只核对其引用消费者，防止误解析 Reactive 源码 |

“完整兼容 Markdown”以本站旧引擎已经支持或宽容处理的行为为基线，不扩展成任意脚本、
任意 CSS 或任意浏览器应用执行。图片、音频、投票等业务权限仍由站点负责。
表情包与用户名片不因本轮统一而新增到博客 / 剪贴板正文语法。

只读扫描本地开发库中未软删的 4,909 篇博客与 196 条剪贴板，共 **5,105 篇**，均标为

| 结果 | 数量及解释 |
|---|---|
| 无编译诊断 | 5,085 篇；尚不代表逐篇排版等价 |
| 有错误或警告 | 20 篇；其中 6 篇编译失败，15 篇带警告，1 篇两者重叠 |
| 表达式误激活 | 未发现；静态扫描命中的两处双花括号都在 LaTeX 内，被正确保护 |
| 有效组件意外激活 | 未发现；另有 2 篇未知 / 不规范角括号标签产生诊断 |
| HTML 相关诊断 | 13 篇；包含明确渲染测试、历史标签、内嵌位图和富文本复制内容 |
| 数学相关诊断 | 2 篇；分别由乱码、未配对定界符触发 |
| 节点预算拒绝 | 3 篇正常长篇诗文 |

逐项核对已确认：测试文章、脚本试验、代码粘贴和多余闭标签占了一部分，不能把
“20 篇有诊断”当作“20 篇正常内容完全损坏”。实际需要保住的行为包括长文可读、
HTML 净化后保留正文、有效历史内嵌图片，以及异常片段不拖垮整篇。

这些数据来自**本地开发库快照**，不是当前生产库结论；未包括引用展开后的全部变体、
全量 MathJax 与浏览器排版对比。正文、标题、作者、内容 ID 和完整扫描载荷不纳入仓库。
实施时将最小复现匿名化为夹具，完整报告只写受控临时目录。

### 2.3 性能与预算

0.7.0 的独立 Node 进程实测如下。保留站点 `markdownBreaks: true`，临时将节点预算
放宽至 100,000 以测成功编译；每项先记录首次调用，再预热 3 次、测量 7 次取中位数。
不含包加载、读取、GC、React / DOM 渲染或业务请求。

| 场景 | 字符数 | 最终 AST 节点 | 首次 / 预热后中位 |
|---|---:|---:|---:|
| 单段纯文本 | 200,000 | 2 | 11 / 3.8 ms |
| 约 9,500 个普通段落 | 200,000 | 19,048 | 133 / 104 ms |
| 长篇诗文 A | 178,480 | 16,951 | 372 / 272 ms |
| 长篇诗文 B | 197,541 | 23,188 | 603 / 495 ms |
| 长篇诗文 C | 184,687 | 22,600 | 614 / 509 ms |

节点预算统计解析中累计创建的节点，含中间节点，不能与最终 AST 数量完全等同。
“20 万字几毫秒”适用于部分低结构复杂度场景，不能据此估算分段、格式、公式、图表或
完整页面成本。站点当前 15,000 阈值的注释依据仍是 0.5.3，必须按本轮版本重新标定。
测试使用 100,000 只是观测手段，不直接成为生产阈值。

## 3. 架构决策

### 3.1 一套引擎、一个作者入口，保留准确的格式契约

1. 博客和剪贴板的 Markdown 与 Reactive 正文都进入统一的准备、编译、渲染管线。
   `format` 不再决定“用新引擎还是旧引擎”，百分比不再决定增强正文是否能交互。
2. 暂时保留数据库和 API 的 `format`、`syntax_version`，不为了界面统一批量把旧
   Markdown 改标为 Reactive。旧消费者仍需要这些字段，源码版本迁移也仍需要依据。
3. 共用编辑器从上游分析 / AST 识别代码块、公式等屏蔽区之外的增强语法，自动维护
   effective format；插入组件与手写组件遵循同一规则，保存时提交明确格式。
4. 已有 Reactive 正文保留其格式与语法版本，删除一个组件不自动降级。草稿把原文、
   effective format 和语法版本一同恢复；旧草稿也须兼容。
5. API 旧调用方省略格式继续遵循现有的创建默认、更新保留规则；显式格式值保持准确。
   API 作者写增强源码时须提供 Reactive 格式。对解析器确认包含有效增强语法、写入格式
   却为 Markdown 的请求，返回具名的 400 格式不匹配错误，提示提供 Reactive 格式或将
   示例写进代码；不存成会被旧消费者误解析的 Markdown。普通旧请求行为有独立回归。
6. 自动识别复用上游语法事实，覆盖控件、表达式、声明、主题等；不用全文正则猜测
   `{{` 或 `<tag>`，也不把代码 / LaTeX 里的示例自动升级。

实现前以契约测试固定格式推导与旧 API 行为。未来删除字段应另有完整消费者迁移，
不在本轮通过改默认值隐式完成。字面语法继续使用 Markdown 转义或代码标记表达，
本轮没有发现需要强制所有作者切换模式的存量表达式冲突。

### 3.2 统一编译配置与兼容层

- `src/lib/reactive/host-components.ts` 中的站点配置作为共同入口；阅读、预览 worker、
  作者分析、迁移、发布快照、导出、摘要和搜索的相关配置从同一处派生。
- 主动区分普通 Markdown 换行兼容与 Reactive 原生语义，验收对应实际输出，不能只
  为减少节点而改变诗文换行。格式推导后的预览与保存后阅读必须一致。
- 优先通过上游修复 / 明确公共扩展点补兼容，锁定交付版本；需要站点适配时集中维护，
  不改 `node_modules`，不在多个页面复制一套解析器或净化策略。
- 兼容 HTML 时，对齐旧管线的允许标签、属性、URL 和净化后正文语义。未知属性可剥离，
  保留可读子节点；危险能力沿用拒绝策略，不把整个有效段落退成大片 HTML 源码。
- 不启用会把整篇分流到原生 HTML iframe 的 capability flags；不引入任意脚本执行。
  本站 iframe 嵌入约定及站点安全边界继续遵守 `../../CLAUDE.md` 和 `docs/architecture.md`。

### 3.3 故障与回滚

- 普通阅读默认交互；SSR 先给静态初始状态，再水合为交互。预览、打印、静态导出只读。
- 历史无效 HTML、未闭合数学和未知普通标签应局部容错。新写入的无效 Reactive 结构
  仍给出诊断并保留草稿，不能静默发布丢正文的产物。
- 临时旧引擎开关只用于迁移与事故回退，限定适用格式和退出阶段；Reactive 源码始终
  不送进旧 Markdown 解析器。最终常规路径不按兼容警告永久切回旧引擎。
- AST 快照是可重建的编译缓存，不是跨版本独立备份。签名不符继续判 stale，故障时
  也不拿旧正文冒充当前版本；源码迁移后的回滚必须同时匹配代码和数据。

## 6. P2：补齐 Markdown 兼容与资源预算

### 6.1 逐类修复

| 类别 | 处理要求 | 验收 |
|---|---|---|
| 超长普通正文 | 重标节点 / 解析工作 / 深度预算；评估静态文本与交互工作分别计量、分块与受控 worker | 三篇约 18–20 万字符诗文均完整可读，尾段不丢；密集与嵌套输入仍受约束 |

### 8.1 工具栏信息架构

```text
Insert ▾  Components ▾  上传图片  插入引用  |  撤销 / 重做  更多
```

| 位置 | 内容与行为 |
|---|---|
| Insert | 标题、粗体、斜体、删除线、列表 / 缩进、引用块、分隔线、行内 / 块级代码、公式、表格、链接、外链图片和 Unicode 表情；按文字 / 列表 / 内容分组 |

| 插入引用 | 既有图床、音频、剪贴板、投票、收藏夹；搜索、可见性标记、键盘选择和正确 token 插入 |

| 更多 | 导出 HTML、打印 / PDF、格式化等低频动作；不得丢失已有功能 |
| 视图切换 | 编辑 / 并排 / 预览独立放在编辑器视图位置；手机只呈现可用视图 |
| 诊断与状态 | 默认收起诊断面板；显示数量、pending / 失败状态，点击定位；补全保留输入提示与快捷键 |
