# 计划与待办

这里维护尚待行动或决定的工作。每项给出下一步及结束条件。方案正文保留设计与验收方法，已交付的设计和当时的验证记录在归档分组。

## 1. 待办与验收

| 主题 | 下一步 | 何时关闭 |
| --- | --- | --- |
| 讨论渲染验收 | 复核桌面与移动端旧消息样本、长列表、流式输出和滚动，记录首屏编译耗时与内存 | 有设备、样本规模、测量值与站长视觉复核结果 |
| 编辑器实机验收 | 记录桌面与移动中文 IME、长文输入与预览、慢网络引用和真实打印结果 | 有设备、输入样本、观察结果及尚存限制 |
| 格式转换器验收 | 核对桌面浏览器、真实 iPhone/Android 与 iframe。测近限额样本的耗时和内存表现，独立解码音频输出以核对时长、声道及非静音 | 每种受测方向有输入、设备和输出证据，缺测项明确 |
| 每日一言旧共鸣 | 先只读统计存量重复组合、付费次数与金额，再由站长决定是否补偿 | 统计与处理决定均有记录 |
| 发布核对 | 发布人员按 `docs/deploy.md` §4 核对目标库的迁移登记、一言累计保护与公开搜索索引回填 | 有对应环境的迁移与发布记录 |
| 前端样式维护 | 按 `docs/plan/maintenance-plan.md` §1 逐项核对仍有消费方的样式，按受影响的页面和视口验收 | 已处理或明确撤销的事项从清单移出 |
| 可见性轨迹视图 | 确定站长入口、排序和分页，再核对现有只读查询，设计见 `docs/plan/maintenance-plan.md` §3 | 站长可查完整变更记录，或已决定撤销 |

## 2. 待决策与候选

| 主题 | 启动条件或待决定的问题 |
| --- | --- |
| 故事区重做 | 确认作品试点与作者授权，再按 `docs/plan/story-rebuild-plan.md` 实施。工具与出版分别见 `docs/plan/story-review-tooling.md`、`docs/plan/story-editorial-design.md` |
| 异文第二章、切页动画 | 确定游戏章节或动效试点后，再按 `docs/plan/yiwen-chapter-two.md`、`docs/plan/page-transition-plan.md` 验收 |
| 编辑器扩展 | 明确就地装饰、表格辅助或大纲的实际编辑需求后单独选做 |
| 转换器功能缺口 | 中文可搜索 PDF 需要字体许可及文字层验证。HTML、DOCX 排版导出 PDF 需要选定执行环境。引入服务端前单独评审本地文件边界 |
| ReactiveMD 扩展 | 决定是否需要响应头观测；稳定章节锚点由外部分享需求触发，数学扩展由具体不兼容的语料触发 |
| 手工间扩展 | 选择要试作的玩法后开新任务，原三款游戏的发布经过见 `docs/archive/craft-games-design.md` |

## 3. 开工与交付

小改动直接更新实现与读者使用的说明。需要分期交付或产品决策时再开计划，写清范围、下一步及验收条件。

交付时将当前行为写入指南或模块手册，把部署与回退条件交给运行手册。保留仍有用的取舍和带日期的证据。核对文档、配置及源码的入链，使维护者从现行手册即可完成操作。把剩余验收或发布核对拆成可关闭的事项，再将结案材料移入 `docs/archive/` 或交由 Git 历史保存。新增和移动文档的登记、互指与旧地址处理见 `docs/README.md`。
